# Button

Button triggers a user-initiated action - submitting a form, confirming a decision, opening a
dialog, starting a workflow. Visual emphasis (`appearance`) and semantic intent (`tone`) are
separate props, so a matter's severity doesn't dictate how loud it looks.

<Canvas of={ButtonStories.Playground} />

## When to use

- Submitting or saving a form.
- Continuing to the next step in a flow.
- Opening a dialog or a menu.
- Confirming or cancelling a decision.
- Warning or destructive/error actions.

## When not to use

- **For navigation.** Use `LinkButton` - it looks like a button but behaves like a link (right-click,
  open in new tab, no `preventDefault` on click).
- **For an icon-only control.** Button always requires a visible label. Use `IconButton`.
- **For a toggleable selected state.** Use `ToggleButton` or `ToggleIconButton`.
- **As a bare loading indicator with no user action attached.** Use `Spinner` directly.
- **To recreate button behavior with ARIA roles on a non-button element.** Render a native `button`.

## Anatomy

<Canvas of={ButtonStories.Content} />

1. **Root** - a native `button`. Always required.
2. **Leading** - either `iconBefore`, or the loading `Spinner` when `isLoading` is true. The two
   never appear together; loading replaces the leading icon rather than sitting beside it.
3. **Content** - the visible label. Required, and always stays visible - even while loading.
4. **Trailing** - `iconAfter`, unaffected by loading.

## Usage guidance

### Appearance versus tone

`appearance` sets emphasis (`default`, `primary`, `subtle`); `tone` sets semantic intent (`neutral`,
`warning`, `error`). They're independent props, but **tone only changes Button's
appearance when `appearance="primary"`** - `default` and `subtle` render identically across every
tone value. Setting `tone="error"` on a `default` button is valid but has no visual effect; if a
non-primary action needs to look different, that's a signal to reconsider the appearance, not to
expect tone to carry it. See Variants.

### Icon usage

Icons render at one fixed size regardless of `size` - Button intentionally has no icon-size prop.
Use `iconBefore` and `iconAfter` for a labelled button with a supporting icon; never as a
replacement for the label. See Edge Cases for why an icon-only Button breaks accessibility.

### Loading behaviour

Setting `isLoading` swaps the leading icon for a `Spinner`, keeps the label visible so the action
stays legible, sets `aria-busy`, and suppresses `onClick` - all without changing the button's width.
Don't pair `isLoading` with a separate disabled-looking treatment; the loading state already
communicates "don't click this again."

### Full width

Set `isFullWidth` when a button must fill its container - a form footer, a mobile action bar. It's a
layout escape hatch, not a default; most buttons should size to their label.

### Focus and hover

Keyboard focus shows the same background fill as hover, on top of the outline ring from the shared
`FocusRing` primitive - a keyboard user sees both signals together rather than a ring on an
otherwise-unchanged button. This is consistent with how Avatar and Checkbox tie focus into their
hover-equivalent treatment; don't add a focus style that looks unrelated to hover.

## Do / Don't

**Do** use `tone` together with `appearance="primary"` for warning or destructive actions.

```tsx
<Button appearance="primary" tone="error">
  Delete matter
</Button>
```

**Don't** set `tone` on a `default` or `subtle` button expecting it to change how it looks.

```tsx
<Button tone="error">Delete matter</Button>
```

---

**Do** keep the label visible through a loading state.

```tsx
<Button appearance="primary" isLoading>
  Save matter
</Button>
```

**Don't** strip the label down to an icon or a spinner alone.

```tsx
<Button appearance="primary" isLoading aria-label="Save" />
```

---

**Do** use `LinkButton` when the control navigates.

```tsx
<LinkButton href="/matters/new">Start a new matter</LinkButton>
```

**Don't** wire a `Button` to navigation with `onClick`.

```tsx
<Button onClick={() => navigate('/matters/new')}>Start a new matter</Button>
```

## Related components

- **IconButton** - for icon-only actions.
- **LinkButton** - for navigation styled as a button.
- **ToggleButton** / **ToggleIconButton** - for a selected/unselected state.
- **Spinner** - the primitive Button renders internally while loading.
- **FocusRing** - the shared focus treatment Button composes rather than styling its own.
