<Section title="Behavior">

<Subsection title="States">

Checked and unchecked come from `checked` or `defaultChecked`. `indeterminate`, `invalid`, and
`disabled` are separate props that each change the look. Invalid draws the box in the error color;
disabled dims the box and the label.

<Example of={CheckboxStories.States} />

</Subsection>

<Subsection title="Partial selection">

Set `indeterminate` on a checkbox that stands for a group whose items are only partly selected,
such as a "select all" above a list. It shows a dash whatever `checked` is, and it doesn't change on
its own: a click still toggles `checked` and calls `onCheckedChange`, and you work out the next
`indeterminate` from the items.

</Subsection>

<Subsection title="Controlled or uncontrolled">

Pass `checked` with `onCheckedChange` to keep the value in your state, or `defaultChecked` to let
the input keep it. `onCheckedChange` gets the next value as a boolean, then the change event.

</Subsection>

<Subsection title="Checkbox Group">

Checkbox Group renders a `fieldset` with your `label` as its `legend`, then the options, then
`errorMessage`. Pass `options` and it renders a Checkbox for each, gives them one `name`, and keeps
the checked values as an array in `value` or `defaultValue`. Pass `children` instead for a layout of
your own; the group then passes those checkboxes nothing, so set their names, values, and states
yourself.

Options stack by default; `orientation="horizontal"` sets them in a row that wraps. `required` on
the group only adds the `*` after the legend. It doesn't make any checkbox required, so check that
at least one is chosen and show `errorMessage` with `invalid` when none is.

<Example of={CheckboxStories.GroupVariants} />

</Subsection>

<Subsection title="Labels">

The box sits before the label and is centered on it, so when a label wraps to several lines the box
lines up with the middle of the text, not the first line. Keep labels short enough to fit on one
line where you can.

<Example of={CheckboxStories.Content} caption="Content: label text, required, a checkbox named by aria-label, a long label, and checkboxes in a fieldset, a table, and a form." />

</Subsection>

<Subsection title="Focus and hover">

Hover, press, and keyboard focus show a round overlay behind the box, in the brand color when it's
checked or indeterminate and in a neutral color otherwise. Keyboard focus adds the shared Focus Ring
around the box. An invalid checkbox keeps the neutral overlay in every state.

</Subsection>

  <Checkbox label="Trust update" />
</Dont>

  <Checkbox aria-label="Select Probate review" />

  <CheckboxGroup
    label="Send matter updates by"
    invalid
    errorMessage="Choose at least one way to send updates."

      { value: 'email', label: 'Email' },

  />

<Section title="Accessibility">

- Checkbox renders a native `input type="checkbox"` inside a `label`, so it's focusable, announced
  as a checkbox, toggled by Space, and named by the label text. Don't rebuild it with
  `role="checkbox"` on another element.
- Without a visible label, name it with `aria-label` or `aria-labelledby`. Nothing warns you when
  both are missing.
- `indeterminate` sets the input's native `indeterminate` and `aria-checked="mixed"`, so it's
  announced as mixed, not as checked or unchecked.
- `invalid` sets `aria-invalid`. Connect a message to a single checkbox with `aria-describedby`.
  Checkbox Group connects its `description` and `errorMessage` for you, to the fieldset and to each
  checkbox from `options`.
- `disabled` and `required` are the native attributes: a disabled checkbox leaves the tab order. The
  `*` is part of the label text, so it's read with the name.
- Checkbox Group is a `fieldset` named by its `legend`, so assistive technology can read the
  question with the options. `invalid` on the group also sets `aria-invalid` on the fieldset.

<Keyboard>
  <Key keys="Tab">Moves focus to the checkbox. A disabled checkbox is skipped.</Key>
  <Key keys="Space">Toggles the checkbox.</Key>
</Keyboard>

</Section>
