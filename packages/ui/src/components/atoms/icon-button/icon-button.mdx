<Section title="When to use">

<Usage>
<UseFor>

- A familiar action whose icon is clear on its own: search, edit, close, more actions.
- A compact row of actions, such as a toolbar or a table row.
- Opening a menu from a "more actions" icon, with `isExpanded`.

</UseFor>
<UseInstead>

- **An action the icon can't explain alone:** <DocLink to="Components/Actions/Button" />, with a visible label and an icon beside it if it helps.
- **A selected or unselected state:** <DocLink to="Components/Actions/Toggle Icon Button" />.
- **Navigation:** <DocLink to="Components/Navigation/Link Button" />. Icon Button is a native button, so it can't be opened in a new tab.
- **Loading with no action attached:** <DocLink to="Components/Feedback/Spinner" /> on its own.

</UseInstead>
</Usage>

<Section title="Variants">

`appearance` sets how much attention the button draws: `default` is outlined, `primary` has the
brand fill, and `subtle` has no border and no fill until hover. There's no `tone`, so there's no
warning or error look; give a destructive action a labelled <DocLink to="Components/Actions/Button" />
instead.

Icon Button still takes this older `appearance` prop, where Button now takes `prominence` and
`tone`; the change is part of the pending Button-family revision.

<Example of={IconButtonStories.Variants} />

<Subsection title="Sizes">

Four squares, from `xs` (24px) to `lg` (48px), on the same control heights as Button so they line up
in a row. The corner radius grows with the size. The icon stays its default size at every button
size, and there's no prop to change it.

<Example of={IconButtonStories.Sizes} />

</Subsection>

<Subsection title="Shape">

`square` follows the size's corner radius; `round` is a full circle at every size. Use one shape
across a toolbar, not a mix.

</Subsection>

<Subsection title="On dark surfaces">

Set `isInverse` on an Icon Button that sits on a dark or bold surface, such as a Banner. It drops the
fill and border, uses the inverse icon color, and swaps the dark hover and press overlays for light
ones. It looks the same for every appearance. Disabled flattens it the same way it flattens the
appearance.

<Example of={IconButtonStories.Inverse} />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Tooltip">

Icon Button shows a tooltip on hover and keyboard focus, after a short delay. With no `tooltip`
prop, a string `aria-label` is the tooltip text. Pass `tooltip` for different text, or
`tooltip={false}` for none. Icon Button can't read the text `aria-labelledby` points to, so with
it, set `tooltip` yourself; it warns in development otherwise. Inside your own
<DocLink to="Components/Overlays/Tooltip" />, it skips its own, so two never stack. A disabled Icon
Button still shows its tooltip on hover.

<Example of={IconButtonStories.Content} caption="Where the tooltip comes from, an external Tooltip, and a toolbar in a card." />

</Subsection>

<Subsection title="Loading">

`isLoading` swaps the icon for a Spinner and ignores clicks. The square keeps its size, so nothing
around it moves. The button stays focusable and keeps its name, and `aria-busy` tells assistive
technology the action is running.

</Subsection>

<Subsection title="Opening a menu or panel">

On an Icon Button that opens a menu or panel, set `isExpanded` to whether it's open, as on Button.
It sets `aria-expanded` to match and keeps the hover fill while open. Leave it unset on a button that
doesn't open anything. <DocLink to="Components/Actions/Dropdown Menu" /> wires its trigger for you.
A "more actions" button uses `MoreVertIcon`, the vertical dots, as Dropdown Menu and Table's row
actions do.

</Subsection>

<Subsection title="Focus and hover">

Keyboard focus shows the hover fill together with the shared Focus Ring, so a keyboard user sees both
signals at once.

<Example of={IconButtonStories.States} />

</Subsection>

  </IconButton>

<Section title="Accessibility">

- Icon Button renders a native `button`, so it's focusable, announced as a button, and activated by
  Enter and Space with no extra code. `type` defaults to `button`, so it submits a form only when
  you ask for `submit`.
- There's no visible text, so the accessible name comes from `aria-label` or `aria-labelledby`.
  Icon Button warns in development when both are missing. Name the action ("Delete matter"), not the
  icon ("Trash").
- The icon and the loading Spinner are hidden from assistive technology.
- While the tooltip shows, it's linked to the button with `aria-describedby`, so it adds a
  description and never replaces the name.
- `disabled` is the native attribute: the button leaves the tab order. A loading button stays
  focusable, with `aria-busy` and `aria-disabled`, so focus doesn't jump while the action runs.
- `isExpanded` sets `aria-expanded` on a button that opens a menu or panel: `true` while it's open, `false` while it's closed.

<Keyboard>
  <Key keys="Tab">Moves focus to the button and shows its tooltip. A disabled button is skipped.</Key>
  <Key keys="Enter">Activates the button, unless it's loading.</Key>
  <Key keys="Space">Activates the button, unless it's loading.</Key>
  <Key keys="Escape">Hides the tooltip.</Key>
</Keyboard>
