# Link Button

LinkButton is navigation that looks like a button. It renders a native anchor with Button's visual
system - `appearance`, `tone`, `size`, icons, loading - so a page can style a navigational action
identically to a triggered one without giving up anchor semantics (right-click, open in new tab,
middle-click to open in a background tab).

<Canvas of={LinkButtonStories.Playground} />

## When to use

- Primary or secondary navigation styled with the same visual weight as an action button.
- A call-to-action that takes the user to a new page or route.
- External links that need Button-family styling.

## When not to use

- **For a page-local action that doesn't navigate.** Use `Button` - an anchor with no real
  destination is a keyboard-trap and screen-reader trust problem waiting to happen.
- **For submitting a form or changing state.** Use `Button type="submit"` or a plain `Button`.
- **For an icon-only control.** LinkButton always requires a visible label; there's no icon-only
  variant, matching Button.

## Anatomy

<Canvas of={LinkButtonStories.Content} />

1. **Root** - a native `a`, always requiring `href`.
2. **Leading** - either `iconBefore`, or the loading `Spinner` when `isLoading` is true, exactly like
   Button.
3. **Content** - the visible label. Required, and stays visible while loading.
4. **Trailing** - `iconAfter`, unaffected by loading.

## Usage guidance

### It shares Button's visual system, not its element

`appearance`, `tone`, `size`, `iconBefore`/`iconAfter`, and `isLoading` all behave exactly as they do
on `Button` - including the same rule that **`tone` only changes anything when
`appearance="primary"`**. See Variants, and see Button's Docs for the full explanation.

### On dark surfaces

`isInverse` is the on-dark treatment, shared with `Button` - for a LinkButton placed on a dark or
bold-colored surface such as `Banner`. It renders a transparent fill with inverse content and the
white *subtle* hover/press overlays. `isDisabled` flattens it the same way it flattens `tone`. See the
Inverse story.

### Disabled is simulated, not native

Anchors have no `disabled` attribute. Setting `isDisabled` instead applies `aria-disabled="true"`,
`tabindex="-1"`, and suppresses the click handler - but the `href` itself is still present in the
DOM. Don't treat a disabled LinkButton as equivalent to a disabled native `button`; anything that
reads raw markup instead of respecting ARIA state can still navigate through it. See Edge Cases.

### `rel` is filled in automatically for `target="_blank"`

When `target="_blank"` is set and no `rel` is provided, LinkButton adds `rel="noopener noreferrer"`
for you. Pass `rel` explicitly only when you need something different - you don't need to add the
security defaults yourself.

## Do / Don't

**Do** let `rel` default when opening in a new tab.

```tsx
<LinkButton href="https://example.com" target="_blank">
  External site
</LinkButton>
```

**Don't** manually re-add the same defaults - it's redundant, and if you overwrite `rel` you may
accidentally drop them.

```tsx
<LinkButton href="https://example.com" target="_blank" rel="noopener noreferrer">
  External site
</LinkButton>
```

---

**Do** use `Button` for an action that doesn't navigate anywhere.

```tsx
<Button onClick={openDialog}>Add note</Button>
```

**Don't** give a non-navigating action an `href` just to reuse LinkButton's styling.

```tsx
<LinkButton href="#" onClick={openDialog}>
  Add note
</LinkButton>
```

---

**Do** treat a disabled LinkButton as a visual/interactive state layered on a real link.

```tsx
<LinkButton href="/clients" isDisabled>
  Open client
</LinkButton>
```

**Don't** assume `isDisabled` removes the destination - the `href` is still there. Remove or guard
the route server-side if it truly must be unreachable.

## Related components

- **Button** - shares this component's entire visual system; use it when there's no navigation.
- **Link** - for inline, text-level navigation without Button styling.
- **IconButton** - for an icon-only action.
