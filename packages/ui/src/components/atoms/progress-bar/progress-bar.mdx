- An upload, an import, or a document that's being generated, when you can measure how far along it is.
- Setup or onboarding completion, as a percentage.
- A compact completion summary on a card or a tile, with the circular variant.

</UseFor>

- **No known percentage:** <DocLink to="Components/Feedback/Spinner" />. Progress Bar has no indeterminate mode.

- **A value the user sets:** <DocLink to="Components/Forms/Slider" />. Progress Bar is read-only.

</UseInstead>

<Section title="Variants">

`variant` picks the form. Use `linear` where there's width to fill: a card, a list row, a form step.
Use `circular` for a compact summary, such as a dashboard tile. Both take the same `value`.

<Example of={ProgressBarStories.Variants} />

<Subsection title="Sizes">

`size` sets the thickness. Linear bars are 24, 32, or 40px tall for `sm`, `md`, and `lg`, with the
fill 4px in from the track's edges. The circular ring is 72px across at every size; only its stroke
gets thicker. Neither variant sets its own width or shows any text.

<Example of={ProgressBarStories.Sizes} />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Value">

`value` runs from 0 to 100. Any other number is clamped, for both the fill and what's announced:
below 0 and `NaN` show 0, above 100 shows 100. At 0 a linear bar shows only its track, and the
circular ring isn't drawn at all. At 100 the fill reaches the end of the track and the ring closes.

<Example of={ProgressBarStories.States} />

<Example of={ProgressBarStories.EdgeCases} caption="Out-of-range values, a narrow container, and a dark surface." />

</Subsection>

<Subsection title="Announced value">

Screen readers announce the value as a percentage. `getValueText` replaces that with words, such as
"6 of 10 documents prepared", without changing the fill. It gets the clamped value.

<Example of={ProgressBarStories.Content} caption="In context: document generation, an upload, a roadmap summary, and custom value text." />

</Subsection>

<Subsection title="Motion">

When `value` changes, the fill eases to its new size with the `fade-quick` motion recipe (150ms).
With reduced motion it changes at once. Reaching or leaving 0 shows or hides the circular ring at
once either way.

</Subsection>

</Section>

<Section title="Do and don't">

<Guidelines>
<Do caption="Name the process with label, so screen readers say what's progressing." code={`<ProgressBar value={42} label="Generating document package" />`}>
  <ProgressBar value={42} label="Generating document package" />
</Do>
<Dont
  caption="Leave the bar unnamed and rely on a percentage shown beside it, which screen readers don't connect to the bar."
  code={`<span>42%</span>
<ProgressBar value={42} />`}
/>
<Do caption="Use Spinner when you can't measure how far along the work is." code={`<Spinner label="Loading matters" />`}>
  <Spinner label="Loading matters" />
</Do>
<Dont caption="Set a made-up value just to show that something is loading." code={`<ProgressBar value={30} label="Loading matters" />`}>
  <ProgressBar value={30} label="Loading matters" />
</Dont>
<Do
  caption="Put counted progress in getValueText, and keep label for the name."
  code={`<ProgressBar
  value={60}
  label="Preparing documents"
  getValueText={() => '6 of 10 documents prepared'}
/>`}
>
  <ProgressBar value={60} label="Preparing documents" getValueText={() => '6 of 10 documents prepared'} />
</Do>
<Dont
  caption="Put the count in label, where it's read as the name and the value is still announced as a percentage."
  code={`<ProgressBar value={60} label="Preparing documents, 6 of 10 done" />`}
/>
</Guidelines>

<Section title="Accessibility">

- Progress Bar renders a `div` with `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax="100"`,
  and `aria-valuenow` set to the clamped value.
- `label` becomes its `aria-label`. An `aria-label` you pass wins over `aria-labelledby`, which wins
  over `label`; only one is set. With none of them the bar has no name, so always name the process.
- `getValueText` sets `aria-valuetext`. Without it, the value is announced as a percentage.
- The track, the fill, and the SVG are hidden from assistive technology, and the component shows no
  text. When sighted users need the number, show it nearby yourself.
- It isn't focusable, has no keyboard interaction, and isn't a live region, so value changes aren't
  announced on their own.

</Section>
