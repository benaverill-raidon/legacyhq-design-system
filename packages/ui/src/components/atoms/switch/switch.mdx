# Switch

Switch lets a user immediately toggle a single setting between enabled and disabled - the state
takes effect right away, with no separate confirmation step.

<Canvas of={SwitchStories.Playground} />

## When to use

- A binary setting that takes effect immediately (notifications, a feature flag, a preference).
- A persistent on/off state the user can flip directly, without a form submission.

## When not to use

- **Selecting one option from a group of several.** Use `RadioGroup`.
- **Selecting any number of options from a list.** Use `Checkbox`.
- **An action that needs confirmation before applying**, or a one-time form choice rather than an
  immediate state change. Use `Checkbox` instead.

## Anatomy

<Canvas of={SwitchStories.Content} />

- **Root** - a `label` wrapping the whole control, so clicking the label text toggles the switch.
- **Input** - the native `input[type="checkbox"]` with `role="switch"`, visually hidden but present
  and focusable.
- **Indicator** - the track, thumb, and a private check/X mark at each end of the track. These marks
  are decorative CSS anatomy, not shared icon-library assets.
- **Label text** - optional. When absent, `aria-label` or `aria-labelledby` is required.

## Usage guidance

### Sizes are the only variant

`md` (the default) and `sm` scale the track, thumb, and travel distance together - see Sizes. The
on/off marks stay a constant 12px at both sizes.

### Loading

`isLoading` blocks toggling and sets `aria-busy="true"`, but deliberately does **not** set native
`disabled` - the control stays focusable and reachable by Tab, communicating "busy" rather than
"unavailable." Figma's `isLoading` artwork has no visible difference from the resting state; this
implementation additionally replaces the visible on/off mark with a small `Spinner` in the same
slot - not on the thumb, so it doesn't compete with the thumb's own slide animation - inheriting
that slot's color with no override of its own. This is a usability improvement beyond the literal
mockup. Hover/pressed track treatment is also suppressed while loading, the same way `disabled`
already does - see States.

### Verifying interaction states

`data-force-state` pins hover/pressed as a static Storybook reference (documentation-only, not part
of the public API) - the same convention Button and Checkbox use. Focus preview instead uses the
shared Focus Ring primitive's own `data-force-state="focus"` support on the input. See States for
both the pinned reference states and a live, click-driven example.

### Reduced motion

The thumb's slide and press animation respects `prefers-reduced-motion: reduce` - see Edge Cases.

## Do / Don't

**Do** use a concise, state-neutral label that describes the setting.

```tsx
<Switch label="Email notifications" />
```

**Don't** phrase the label as an instruction - the switch itself already communicates the action.

```tsx
<Switch label="Turn on email notifications" />
```

---

**Do** give a label-less Switch an accessible name via `aria-label`.

```tsx
<Switch aria-label="Enable standalone setting" />
```

**Don't** omit both `label` and `aria-label` - the control becomes unnamed for assistive technology.

```tsx
<Switch />
```

---

**Do** use `isLoading` while an async toggle is in flight, so it stays focusable and announces busy.

```tsx
<Switch label="Syncing calendar" isLoading defaultChecked />
```

**Don't** use `disabled` for the same purpose - it removes the control from the tab order and reads
as permanently unavailable, not temporarily busy.

```tsx
<Switch label="Syncing calendar" disabled defaultChecked />
```

## Related components

- **Checkbox** - for multi-select or a one-time form choice rather than an immediate state change.
- **RadioGroup** - for selecting one option from several named choices.
