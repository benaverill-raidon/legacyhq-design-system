<Section title="Variants">

Here `tone` is the visual style, not a meaning: `default` has a border and `subtle` has none, in
every state. Selected uses the same fill and text color for both, and only `default` shows the
selected border. Using `tone` for style is a recorded exception to the system's naming, kept on
purpose.

<Subsection title="Sizes">

Four control heights, from `xs` (24px) to `lg` (48px), the same as Button so the two line up in a
row. `lg` also sets the label one type size larger. Icons are the same size at every toggle button
size, and there's no prop to change them.

<Section title="Behavior">

<Subsection title="The parent owns the state">

Toggle Button never changes on its own: `isSelected` comes from your state, and your `onClick` flips
it. When several buttons stand for one choice, such as a view mode, keep the chosen value in the
parent and select the button that matches it. When each option is on or off by itself, such as
bold and italic, give each its own state.

<Example of={ToggleButtonStories.Content} caption="Independent formatting options, a view mode that's one choice, and a pair of filters." />

</Subsection>

<Subsection title="Disabled">

`disabled` is the native attribute, so the button leaves the tab order and ignores
clicks. Disabled looks the same selected or not, but `aria-pressed` still reports the state.

</Subsection>

<Subsection title="Width">

Toggle Buttons size to their label and never wrap it. A label longer than the space overflows its
container, so keep labels short.

</Subsection>

<Subsection title="Focus and hover">

Keyboard focus shows the hover fill together with the shared Focus Ring, selected or not, so a
keyboard user sees both signals at once. A selected button keeps its border and text color and steps
only its fill, to the selected hover and press fills.

<Example of={ToggleButtonStories.States} />

</Subsection>

<Section title="Accessibility">

- Toggle Button renders a native `button`, so it's focusable and activated by Enter and Space with
  no extra code. `type` defaults to `button`, so it submits a form only when you ask for `submit`.
- `isSelected` sets `aria-pressed` to `true` or `false`, so assistive technology announces a toggle
  button, pressed or not pressed. It doesn't use `aria-selected`, `aria-expanded`, or
  `role="switch"`.
- The visible label is the accessible name. Keep it the same in both states; the pressed state
  already says whether it's on. The icons are hidden from assistive technology.
- `disabled` is the native attribute: the button leaves the tab order, and `aria-pressed` stays.

<Keyboard>
  <Key keys="Tab">Moves focus to the button. A disabled button is skipped.</Key>
  <Key keys="Enter">Activates the button, which calls `onClick`, where you flip `isSelected`.</Key>
  <Key keys="Space">Activates the button, which calls `onClick`, where you flip `isSelected`.</Key>
</Keyboard>
