<Section title="Variants">

Here `tone` is the visual style, not a meaning: `default` has a border and `subtle` has none, in
every state. Selected uses the same fill and icon color for both, and only `default` shows the
selected border. Using `tone` for style is a recorded exception to the system's naming, kept on
purpose.

`shape` is separate from both: `square` follows the size's corner radius, and `round` is a full
circle at every size.

<Example of={ToggleIconButtonStories.Variants} />

<Subsection title="Sizes">

Four squares, from `xs` (24px) to `lg` (48px), the same as Icon Button so the two line up in a
toolbar. The corner radius grows with the size. The icon stays its default size at every button
size, and there's no prop to change it.

<Example of={ToggleIconButtonStories.Sizes} />

</Subsection>

<Section title="Behavior">

<Subsection title="The parent owns the state">

Toggle Icon Button never changes on its own: `isSelected` comes from your state, and your `onClick`
flips it. When several buttons stand for one choice, such as grid or list view, keep the chosen
value in the parent and select the button that matches it. When each option is on or off by itself,
such as bold and italic, give each its own state.

<Example of={ToggleIconButtonStories.Content} caption="A view mode that's one choice, independent formatting options, and a favorite." />

</Subsection>

<Subsection title="Tooltip">

Toggle Icon Button has no tooltip of its own, unlike Icon Button. Wrap it in
<DocLink to="Components/Overlays/Tooltip" /> to show its name on hover and keyboard focus; the
tooltip shows on a disabled one too. The `aria-label` stays the name either way.

</Subsection>

<Subsection title="Disabled">

`disabled` is the native attribute, so the button leaves the tab order and ignores
clicks. Disabled looks the same selected or not, but `aria-pressed` still reports the state.

</Subsection>

<Subsection title="Focus and hover">

Keyboard focus shows the hover fill together with the shared Focus Ring, selected or not, so a
keyboard user sees both signals at once. A selected button keeps its border and icon color and steps
only its fill, to the selected hover and press fills.

<Example of={ToggleIconButtonStories.States} />

</Subsection>

</Section>

<Section title="Do and don't">

<Guidelines>
<Do caption="Name it with aria-label, and wrap it in Tooltip to show that name on hover and focus." code={`<Tooltip content="Pin matter">
  <ToggleIconButton aria-label="Pin matter" isSelected={isPinned} onClick={togglePinned}>
    <PinIcon />
  </ToggleIconButton>
</Tooltip>`}>
  <Tooltip content="Pin matter">
    <ToggleIconButton aria-label="Pin matter" isSelected>
      <PinIcon />
    </ToggleIconButton>
  </Tooltip>
</Do>
<Dont
  caption="Name it only with a Tooltip, which describes the button only while it shows, so the button has no name."
  code={`<Tooltip content="Pin matter">
  <ToggleIconButton isSelected={isPinned} onClick={togglePinned}>
    <PinIcon />
  </ToggleIconButton>
</Tooltip>`}
/>
<Do caption="Keep the name the same, and let aria-pressed say whether it's on." code={`<ToggleIconButton aria-label="Favorite" isSelected={isFavorite} onClick={toggleFavorite}>
  {isFavorite ? <StarStarredIcon /> : <StarUnstarredIcon />}
</ToggleIconButton>`}>
  <ToggleIconButton aria-label="Favorite" isSelected>
    <StarStarredIcon />
  </ToggleIconButton>
</Do>
<Dont
  caption="Change the name with the state, so people hear Remove from favorites, pressed, and can't tell what pressing does."
  code={`<ToggleIconButton
  aria-label={isFavorite ? 'Remove from favorites' : 'Add to favorites'}
  isSelected={isFavorite}
>
  <StarStarredIcon />
</ToggleIconButton>`}
/>
<Do caption="Use Toggle Button when there's room for a label." code={`<ToggleButton isSelected={showArchived}>Show archived</ToggleButton>`}>
  <ToggleButton isSelected>Show archived</ToggleButton>
</Do>
<Dont caption="Use an icon that isn't familiar on its own, which people have to guess at." code={`<ToggleIconButton aria-label="Show archived" isSelected={showArchived}>
  <ArchiveIcon />
</ToggleIconButton>`}>
  <ToggleIconButton aria-label="Show archived" isSelected>
    <ArchiveIcon />
  </ToggleIconButton>
</Dont>
</Guidelines>

<Section title="Accessibility">

- Toggle Icon Button renders a native `button`, so it's focusable and activated by Enter and Space
  with no extra code. `type` defaults to `button`, so it submits a form only when you ask for
  `submit`.
- There's no visible text, so the accessible name comes from `aria-label` or `aria-labelledby`. It
  warns in development when both are missing. Name the option ("Bold"), and keep the name the same
  in both states. The icon is hidden from assistive technology.
- `isSelected` sets `aria-pressed` to `true` or `false`, so assistive technology announces a toggle
  button, pressed or not pressed. It doesn't use `aria-selected`, `aria-expanded`, or
  `role="switch"`.
- When it's wrapped in Tooltip, the tooltip is linked with `aria-describedby` while it shows, so it
  adds a description and never replaces the name.
- `disabled` is the native attribute: the button leaves the tab order, and `aria-pressed` stays.

<Keyboard>
  <Key keys="Tab">Moves focus to the button. A disabled button is skipped.</Key>
  <Key keys="Enter">Activates the button, which calls `onClick`, where you flip `isSelected`.</Key>
  <Key keys="Space">Activates the button, which calls `onClick`, where you flip `isSelected`.</Key>
</Keyboard>
