<Subsection title="Truncated or wrapped">

Turn it off for a longer hint, which wraps at 240px. There's no size and no placement prop; the
bubble fits its text.

<Section title="Behavior">

<Subsection title="Showing and hiding">

The tooltip shows `delay` milliseconds (300 by default) after the pointer enters the trigger or the
trigger takes focus, and hides at once when the pointer leaves, focus leaves, or someone presses
Escape, wherever focus is. The pointer can move from the trigger onto the bubble without hiding it
(a strip fills the gap between them), so people who zoom in can read it; it hides when the pointer
leaves both. It fades in with `fade-quick` and leaves at once. `disabled` turns the tooltip off and leaves the trigger as it
is.

A handler you set on the trigger runs first; if it calls `event.preventDefault()`, Tooltip skips
its own show or hide for that event.

<Example of={TooltipStories.Content} caption="Icon Buttons, Toggle Icon Buttons, a disabled trigger, and a Button, each with a tooltip." />

</Subsection>

<Subsection title="Position">

The bubble opens above the trigger, centered, 8px away. Near the edge of the viewport it moves to
the position that fits, below first. It's positioned by Popup, at the end of the page, so an
`overflow: hidden` container doesn't clip it.

It sits above Modal Dialog and Toast Group, with every Popup, so a tooltip on a control inside a
dialog, such as its Close button, shows over the dialog.

<Example of={TooltipStories.EdgeCases} caption="Fallback near the viewport edge, a tooltip on keyboard focus, and one on a dark surface." />

</Subsection>

<Subsection title="Disabled controls">

A disabled control may not get pointer events, so Tooltip wraps a disabled trigger in a `span` that
shows the tooltip on hover. It counts a native `button`, `input`, `select`, or `textarea` with
`disabled`, or a component with `disabled` or `isDisabled`, as disabled. The span isn't focusable,
and a disabled control is skipped by Tab, so keyboard users never see this tooltip. Keep it to what
the control does, as on an enabled one, and don't use it to say why the control is disabled: put the
reason in visible helper text, such as a Field message, where everyone can read it.

</Subsection>

<Subsection title="Icon Button and wrapping components">

Icon Button shows its `aria-label` as a tooltip on its own, and leaves it out inside a Tooltip, so
the two never stack up. Wrap an Icon Button in Tooltip only when the hint should say more than its
name.

Tooltip passes its `ref` and every prop it doesn't use itself to the trigger: `aria-*` and `data-*`
attributes, `role`, `style`, and event handlers. So a component that clones its child, such as
Popup or Dropdown Menu, can wrap a Tooltip, and the attributes it adds still reach the real trigger.

</Subsection>

<Section title="Accessibility">

- Tooltip adds no element around an enabled trigger, which keeps its own role and name. Give the
  trigger a name of its own: visible text, or `aria-label` on an icon-only control.
- While it shows, the bubble is a `role="tooltip"` element at the end of the page, and the trigger's
  `aria-describedby` includes its id, alongside any ids the trigger already had. When it hides, the
  id is removed.
- It shows on keyboard focus as well as hover, and never takes focus itself. It adds no tab stop,
  including the `span` around a disabled trigger.
- Its text is read as a description, not as content people can move to, so it can't hold links,
  buttons, or fields.
- A disabled trigger can't take focus, so its tooltip is shown only on hover.
- Escape hides it however it was shown, by hover or focus, without moving focus. Inside a menu or
  dialog, the first Escape hides the tooltip and the next closes what's under it.
- The bubble can be hovered: moving the pointer onto it keeps it open, so it can be read when zoomed
  in; it hides when the pointer leaves both, when focus leaves the trigger, or on Escape.

<Keyboard>
  <Key keys="Tab">Moves focus to the trigger, which shows the tooltip after the delay. Moving focus away hides it.</Key>
  <Key keys="Escape">Hides a visible tooltip, whether hover or focus showed it. A menu or dialog under it stays open until the next Escape.</Key>
</Keyboard>

</Section>

<Section title="API">

<PropsTable of={TooltipStories} />

Any other prop set on Tooltip, such as an `aria-*` or `data-*` attribute, `role`, `style`, or an
event handler, is passed to the trigger. The value set on Tooltip wins, except that both event
handlers run (the trigger's first), styles merge, `aria-describedby` ids are kept from both, and
`undefined` never removes the trigger's own value.
