<Section title="When to use">

<Usage>
<UseFor>

- A row of search scopes, such as Matters, Documents, and People.
- A bar of active filters above a list.
- Any set of chips that should share one size and wrap together.

</UseFor>
<UseInstead>

- **A set that truncates behind "+N more":** <DocLink to="Components/Data Display/Tag Group" />, with Tags. Chip Group never hides a chip.
- **A row of buttons:** <DocLink to="Components/Actions/Button Group" />.
- **One choice from a few options:** <DocLink to="Components/Forms/Radio" />, or <DocLink to="Components/Forms/Select" /> for a longer list.

</UseInstead>

<Section title="Variants">

<Subsection title="Sizes">

`size` sets every Chip inside the group to `sm` (24px) or `md` (32px), even a Chip inside a wrapper,
returned from a `.map`, or shown conditionally. A `size` on one Chip still wins over the group's.
Leave `size` off and each Chip keeps its own, `md` by default. Filter chips come only in `md`, so
keep them out of an `sm` group.

<Example of={ChipGroupStories.Sizes} />

</Subsection>

<Subsection title="Alignment">

`alignment` sets which edge the chips pack against: `left`, the default, or `right`. It's not Tag
Group's `alignment`, which places that group's overflow tag; Chip Group has no overflow.

<Example of={ChipGroupStories.Alignment} caption="The dashed box shows the group's own bounds." />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Wrapping">

When the row runs out of room, chips wrap onto the next line, with the same 8px gap between lines as
between chips. Every chip stays visible.

<Example of={ChipGroupStories.Wrapping} />

</Subsection>

<Subsection title="Selection stays yours">

Chip Group doesn't coordinate its chips. Search chips are independent toggles, so if only one scope
should be on at a time, the code holding the state turns the others off. Removing a filter chip is
also up to the code that renders it.

<Example of={ChipGroupStories.Content} caption="A scope selector and an active filter bar, both wired to live state." />

</Subsection>

<Subsection title="Mixed content">

A group can hold chips of different modes and disabled chips, which sit in the row like the others.

<Example of={ChipGroupStories.EdgeCases} caption="Edge cases: a single chip, mixed modes, disabled chips, and a dark surface." />

</Subsection>

</Section>

  </ChipGroup>

<Dont
  caption="Set size on each chip. Miss one, and it breaks the row."
  code={`<ChipGroup aria-label="Search scopes">
    <Chip mode="search" label="Matters" size="sm" isSelected />
    <Chip mode="search" label="Documents" size="sm" />
    <Chip mode="search" label="People" />
</ChipGroup>`}
>
  <ChipGroup aria-label="Search scopes">
    <Chip mode="search" label="Matters" size="sm" isSelected />
    <Chip mode="search" label="Documents" size="sm" />
    <Chip mode="search" label="People" />
  </ChipGroup>
</Dont>
<Do
  caption="Name a group that forms a set, so it's announced as one."
  code={`<ChipGroup aria-label="Active filters">{filterChips}</ChipGroup>`}
/>
<Dont
  caption="Leave a set of related chips unnamed. Without a name, the group has no role and isn't announced."
  code={`<ChipGroup>{filterChips}</ChipGroup>`}
/>
<Do
  caption="Keep one-of-a-set selection in your own state, and pass each chip its isSelected."
  code={`<ChipGroup aria-label="Search scope">
    {scopes.map((scope) => (
      <Chip
        key={scope.id}
        mode="search"
        label={scope.label}
        isSelected={scope.id === selected}
        onSelectedChange={() => setSelected(scope.id)}
      />
    ))}
</ChipGroup>`}
/>
<Dont
  caption="Expect the group to turn the other chips off. Each search chip toggles on its own."
  code={`<ChipGroup aria-label="Search scope">
    <Chip mode="search" label="Matters" isSelected={matters} onSelectedChange={setMatters} />
    <Chip mode="search" label="Documents" isSelected={documents} onSelectedChange={setDocuments} />
</ChipGroup>`}
/>
</Guidelines>

<Section title="Accessibility">

- Chip Group renders a `div`. It has `role="group"` only when it's named with `aria-label` or
  `aria-labelledby`; an unnamed group would be a boundary to step through for no benefit.
- It adds no focus or keyboard behavior of its own. Each chip's controls are separate tab stops, in
  the order they appear, and there's no arrow-key movement between chips.
- It doesn't manage selection: each search chip announces its own state with `aria-pressed`.

<Keyboard>
  <Key keys="Tab">Moves to the next chip control in the group, in order. Disabled controls are skipped.</Key>
</Keyboard>

</Section>
