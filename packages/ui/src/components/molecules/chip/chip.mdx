<Section title="Variants">

<Subsection title="Modes">

`mode` changes Chip's shape, so the props are typed per mode: `value` exists only on a filter chip,
`onSelectedChange` only on a search chip, and `onRemove` is required on filter and select chips.

- `filter` is the label, an optional operator, the value, and a remove button. The operator and the
  value open menus.
- `select` is the label and a remove button. There's nothing to open.
- `search` is the label alone, and the label is the control: it toggles the chip on and off. It's
  the only mode with a selected look.

<Example of={ChipStories.Modes} />

</Subsection>

<Subsection title="Sizes">

Two heights: `sm` (24px) and `md` (32px), the default. `size` applies to every segment together.
Filter chips come only in `md`, and an explicit `size="sm"` on one is a type error; an `sm` from an
enclosing Chip Group isn't blocked, so don't put filter chips in an `sm` group.

<Example of={ChipStories.Sizes} />

</Subsection>

<Subsection title="Operator">

`operator` adds a comparison segment between the label and the value. Any filter can have one, not
only dates. Where the operator and the value meet, the line between them is 1px, like every other
seam in the pill.

<Example of={ChipStories.WithOperator} />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Menus">

The operator and the value each open their own Dropdown Menu below the segment, with no search
field, and each keeps its own open state, so one never closes the other. Opening a menu moves focus
to its first item. Choosing an item runs that item's `onSelect`, then closes the menu and returns
focus to the segment; an `onSelect` that calls `event.preventDefault()` keeps it open, for choosing
several values. Escape, Tab out of the menu, or a click outside also closes it.

Each segment takes a `ChipSegment`, whose `sections` are Menu's own sections:

<CodeSample code={`{
    label: React.ReactNode;       // the current operator or value, shown in the segment
    sections: MenuSection[];      // the rows the segment's menu lists
    menuAriaLabel?: string;       // names the menu; defaults to "<label> operator" or "<label> value"
    tooltip?: React.ReactNode;    // shown on hover and focus, such as the full value when it's cut off
}`} />

The menu is named after the property and the segment's role, such as "Due date value", because the
segment's own text is the current value, which says nothing about what choosing does. That default
needs the label as text: a string `label`, or `labelText` when `label` is JSX. Otherwise, pass
`menuAriaLabel`.

</Subsection>

<Subsection title="Selection and removal">

Chip never changes its own state. Activating a search chip calls `onSelectedChange` with the next
value; the remove button calls `onRemove`. Search chips are independent toggles, not a radio group:
several can be on at once, and if only one should be, the code holding the state decides that.

<Example of={ChipStories.Content} caption="A filter bar whose chips can be removed." />

</Subsection>

<Subsection title="States">

The label segment has no hover or press fill in any mode. In `filter` and `select` it names the
property and doesn't act; in `search`, being selected or not is the feedback. The operator, value,
and remove segments, which do act, take the hover and press fills. A selected search chip uses the
selected background, border, and text. `disabled` disables every control in the chip and overrides
selected, border included. The label's icon follows the label's text color through each state.

<Example of={ChipStories.States} caption="Focus is pinned for this reference; hover the operator, value, or remove segment to see their fills." />

</Subsection>

<Subsection title="Long text">

The chip stays on one line and sizes to its text, up to the width of its container. Past that, the
label and the value each end in an ellipsis, giving up width in proportion to their length; the
remove button, `elemBefore`, and `valuePreview` keep their size. Keep labels and values short anyway,
such as "3 people" rather than a list of names, and give a segment that may be cut off a `tooltip`
with its full text.

<Example of={ChipStories.EdgeCases} caption="Edge cases: a long label and value in a 320px container, no elemBefore, and a dark surface." />

</Subsection>

</Section>

<Section title="Accessibility">

- The root is a `div` with no role. In `filter` and `select`, the label segment is plain text, not a
  control.
- A search chip's label segment is a native `button` with `aria-pressed`, the same semantics as
  Toggle Button. Its visible label is its name.
- The operator and value segments are native buttons, named by the label and their own text
  together through `aria-labelledby`, such as "Due date April 15", since their text alone is only
  the current operator or value. With `labelText`, its text stands in for the label. Dropdown Menu
  gives each `aria-haspopup="menu"` and `aria-expanded`, and `aria-controls` while its menu is open,
  with or without a segment `tooltip`.
- Each menu is a Menu, announced as a menu and named "Due date value" or "Due date operator" by
  default, or by `menuAriaLabel`.
- The remove button is a native button named by `removeLabel`, `Remove` plus the label by
  default (`removeAriaLabel` is its deprecated name, still accepted). The default names need the label as text: a string `label`, or `labelText`. A "Remove" tooltip shows on hover and focus; it isn't the button's name, and it's not
  shown while disabled.
- `elemBefore` and `valuePreview` are hidden from assistive technology, so the label and value text
  must carry the meaning.
- `disabled` sets the native attribute on every control in the chip, so they leave the tab order.
- Every control shows the shared Focus Ring, and the focused segment is raised above its neighbors
  so they don't hide the ring.
- Opening a menu moves focus to its first item. Choosing an item, Escape, or Tab out of the menu
  closes it and returns focus to the segment that opened it.

<Keyboard>
  <Key keys="Tab">Moves through the chip's controls in order: the operator, the value, then remove; or the search chip's toggle. Disabled controls are skipped. In a menu, Tab or Shift + Tab closes it and returns focus to its segment.</Key>
  <Key keys="Enter">On a search chip, toggles it. On the operator or value, opens or closes its menu. On remove, calls `onRemove`.</Key>
  <Key keys="Space">The same as Enter. In a menu, Enter or Space chooses the item.</Key>
  <Key keys="Escape">Closes an open menu and returns focus to its segment.</Key>
  <Key keys="Arrow Down">In a menu, moves to the next item, wrapping from the last to the first.</Key>
  <Key keys="Arrow Up">In a menu, moves to the previous item, wrapping from the first to the last.</Key>
  <Key keys="Home">In a menu, moves to the first item.</Key>
  <Key keys="End">In a menu, moves to the last item.</Key>
</Keyboard>

</Section>

label: React.ReactNode;              // required
elemBefore?: React.ReactNode;        // a decorative icon or Avatar; an Avatar is sized to the chip
size?: 'sm' | 'md';                  // defaults to Chip Group's size, else 'md'
disabled?: boolean;                  // disables every control in the chip
id?: string;                         // on the root div
className?: string;                  // added to the root div

// mode="filter"
value: ChipSegment;                  // required
operator?: ChipSegment;
valuePreview?: React.ReactNode;      // decorative, before the value text
onRemove: (event) => void;           // required
removeLabel?: string;                // defaults to "Remove <label>"; removeAriaLabel is its deprecated name
labelText?: string;                  // the label as text, for the built names; set it when label is JSX
size?: 'md';                         // filter chips are md only

// mode="select"
onRemove: (event) => void;           // required
removeLabel?: string;                // defaults to "Remove <label>"; removeAriaLabel is its deprecated name
labelText?: string;                  // the label as text, for the remove button's name

// mode="search"
isSelected?: boolean;                // default false; sets aria-pressed
onSelectedChange?: (isSelected: boolean) => void;`} />
