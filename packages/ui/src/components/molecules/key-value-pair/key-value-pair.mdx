export function EditablePair({ label, initial, size, actionPlacement = 'end' }) {
  const [value, setValue] = React.useState(initial);
  return (
    <KeyValuePair label={label} size={size} underline>
      <InlineEdit value={value} onConfirm={setValue} actionPlacement={actionPlacement}>
        <TextField size={size} context="inline" aria-label={label} iconAfter={<EditIcon color="subtle" />} />
      </InlineEdit>
    </KeyValuePair>
  );
}

<Section title="Variants">

<Subsection title="Static or editable">

Pass `value` for a read-only value, shown as text. For a value people can edit, pass an inline Text
Field, Text Area, or Select as `children`, with `context="inline"`, usually inside Inline Edit so the
change is confirmed or cancelled. `children` replaces `value` when both are set. The control keeps
its own inline look, with its hover fill, but its corners are square inside the row. In Figma, this
is the pair's `context`: `static` or `inline`.

<Example of={KeyValuePairStories.InlineEditable} caption="Text Field and Text Area in Inline Edit, and a Select, beside static pairs." />

</Subsection>

<Subsection title="Sizes">

`sm`, `md`, the default, and `lg` set the row's minimum height to 32, 40, or 48px, the control
heights, and the text to `body-sm`, `body-md`, or `body-lg`. The key and a static value are inset
8px from their column's edge, 12px at `lg`. The size doesn't reach an inline control: give the
control the same `size`, so its height and text match the row.

<Example of={KeyValuePairStories.Sizes} />

</Subsection>

<Subsection title="Underline">

`underline` draws a 1px divider under the row. In a list, it usually goes on every pair but the
last, so the list doesn't end on a line.

<Example of={KeyValuePairStories.Underline} />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Long values">

The key takes 40% of the row at every size, and the value fills the rest; there's no prop to change
the split. Long text wraps in its column. The key stays at the top of the row, and a static value is
centered in the row's height. An inline Text Area with `autoResize` grows the row as it grows, and the
rows below move down.

<Example of={KeyValuePairStories.GrowingNotes} caption="Inline notes that are short, wrapped, and past the six lines they show before scrolling, at each size." />

</Subsection>

<Subsection title="Editing in place">

Put Inline Edit's cancel and confirm buttons at the end of the value, with
`actionPlacement="end"` on the <DocLink to="Components/Forms/Inline Edit" />. They sit 8px past the
field's trailing edge, so the row keeps its height while editing and the pairs below it don't move.
Inline Edit's default placement puts the buttons below the field and makes room for them, which
grows the row. With an inline Text Area that grows, add `actionAlignment="start"` so the buttons
stay level with its first line.

</Subsection>

</Section>

<Section title="Accessibility">

- Key Value Pair renders a `div` holding a `dt` for the key and a `dd` for the value. Inside a Key
  Value List's `dl`, that's a valid description list: screen readers announce the list and its items.
  Outside a `dl`, the `dt` and `dd` aren't valid HTML.
- The key isn't linked to an inline control in the value, so it doesn't name it. Give the control an
  `aria-label`, usually the key's text.
- The pair itself isn't focusable and has no keyboard behavior. An inline control and Inline Edit's
  buttons keep their own focus and keys.
- The key uses the subtle text color and the value the default one, so the value reads first.

</Section>
