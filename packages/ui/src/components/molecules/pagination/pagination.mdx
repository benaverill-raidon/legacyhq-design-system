<Section title="Behavior">

<Subsection title="Controlled">

Pagination keeps no state: it shows `currentPage` of `totalPages` and calls `onPageChange` with the
page someone chose, the page number or the one before or after. Update `currentPage` in response,
from component state or the URL. Choosing the current page calls `onPageChange` with the same page.
`currentPage` is rounded down and clamped between 1 and `totalPages`. Previous is disabled on the
first page and Next on the last. When Previous or Next has focus and reaching the end disables it,
focus moves to the current page, so it isn't lost.

</Subsection>

<Subsection title="Which pages show">

The first and last `boundaryCount` pages always show, and so do `siblingCount` pages on each side of
the current one. A gap of more pages becomes an ellipsis; a gap of exactly one page shows that page,
since it takes the same room. With the defaults of 1, page 1 of 20 shows `1 2 … 20`, and page 10
shows `1 … 9 10 11 … 20`. Raise `siblingCount` for a wider range where there's room.

<Example of={PaginationStories.Composition} caption="Few pages, the middle of a long range, near the start, near the end, and a wider sibling range." />

</Subsection>

<Subsection title="Width">

Page buttons are 32px squares, so a two-digit page is as wide as a one-digit one. The number of
buttons changes as the current page moves, so the row grows and shrinks, and Next moves with it,
near either end of a long range.

</Subsection>

</Section>

<Section title="Accessibility">

- The root is a `nav` landmark named by `aria-label`, "Pagination" by default. Translate it, and
  give each Pagination on a page its own name, or name it by a visible heading with
  `aria-labelledby`, which replaces it. `ariaLabel`, the old name, still works.
- Previous and Next are Icon Buttons named by `previousLabel` and `nextLabel`, which also show as
  their tooltip on hover and focus. At either end, the button is natively `disabled` and leaves the
  tab order; if it had focus, focus moves to the current page.
- Each page is a native `button` named by `getPageLabel`, "Page 3" by default, around the visible
  number. The current page has `aria-current="page"`, so it's announced once, as the current page.
  Pages take Toggle Button's look but not its `aria-pressed`: a page is a position, not an on or
  off option.
- The ellipsis is hidden from assistive technology, so the left-out pages aren't announced; the
  names of the pages on either side, such as "Page 20", say where the range jumps.
- Every control shows the shared Focus Ring.

<Keyboard>
  <Key keys="Tab">Moves focus through Previous, each page, and Next, in order. A disabled Previous or Next is skipped.</Key>
  <Key keys="Enter">Goes to the focused page, or the page before or after.</Key>
  <Key keys="Space">Goes to the focused page, or the page before or after.</Key>
</Keyboard>
