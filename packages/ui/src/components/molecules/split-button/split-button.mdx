<Section title="Variants">

<Subsection title="Appearance and size">

`appearance` styles both halves together. `default` is outlined: the main action is Button's
`secondary` prominence beside an outlined Icon Button. `primary` gives both halves the brand fill.
There's no subtle split button. `appearance` is the older name for this choice; Button itself now
uses `prominence` and `tone`.

`size` sets both halves to the same control height, from `xs` (24px) to `lg` (48px), the same scale
as Button, and the divider matches it.

<Example of={SplitButtonStories.Variants} caption="Default and primary, at every size." />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="The menu">

The caret opens a Menu below the Split Button, lined up with its right edge; if there's no room
there, it opens where it fits best. The menu has no search field. Opening it moves focus to the
first item. Choosing an item runs that item's `onSelect`, then closes the menu and returns focus to
the caret; an `onSelect` that calls `event.preventDefault()` keeps it open. Escape or Tab out of the
menu closes it and returns focus to the caret, and a click outside closes it.

<Example of={SplitButtonStories.Content} caption="Realistic main actions, each with two close alternatives." />

</Subsection>

<Subsection title="Loading and disabled">

`isLoading` shows Button's loading state on the main action: a Spinner centered over the label, with
the button's size unchanged, so nothing around it moves. The caret is disabled until loading ends,
so nobody picks another action while the first one runs.

`disabled` disables both halves, and the divider takes the disabled border color.

<Example of={SplitButtonStories.EdgeCases} caption="Loading, disabled in both appearances, and a menu item reporting the choice." />

</Subsection>

<Subsection title="What each half gets">

`size`, `appearance`, and `disabled` apply to both halves. `onClick`, `iconBefore`, `iconAfter`,
`tone`, a `ref`, and any other button attribute go to the main action only. `id` and `className` go
to the wrapping `div`. There's no full-width Split Button.

</Subsection>

</Section>

<Section title="Accessibility">

- Split Button renders a `div` with no role around two native buttons: the main action, a Button,
  and the caret, an Icon Button. The divider is hidden from assistive technology.
- The main action's label is its accessible name. The caret's name is `secondaryActionLabel`, which
  also shows as its tooltip and names the menu.
- The caret has `aria-haspopup="menu"` and `aria-expanded`, which is `true` while the menu is open,
  when its `aria-controls` points at the menu.
- The menu is a Menu, announced as a menu, with each action a menu item.
- The menu is added at the end of the page, so opening it moves focus to its first item, and
  choosing an item, Escape, or Tab out of it returns focus to the caret. Arrow keys move between
  items.
- While loading, the main action stays focusable, with `aria-busy` and `aria-disabled`, and the
  caret is natively disabled. `disabled` takes both halves out of the tab order.

<Keyboard>
  <Key keys="Tab">Moves to the main action, then to the caret. A disabled half is skipped, and so is the caret while loading. In the menu, Tab or Shift+Tab closes it and returns focus to the caret.</Key>
  <Key keys="Enter">On the main action, runs it unless it's loading. On the caret, opens the menu and moves focus to its first item. On an item, chooses it, closes the menu, and returns focus to the caret.</Key>
  <Key keys="Space">The same as Enter.</Key>
  <Key keys="Escape">Closes the menu and returns focus to the caret.</Key>
  <Key keys="Arrow Down">In the menu, moves to the next item, wrapping from the last to the first.</Key>
  <Key keys="Arrow Up">In the menu, moves to the previous item, wrapping from the first to the last.</Key>
  <Key keys="Home">In the menu, moves to the first item.</Key>
  <Key keys="End">In the menu, moves to the last item.</Key>
</Keyboard>

</Section>
