<Section title="Variants">

Three sizes and two contexts, on Text Area's frame.

<Example of={RichTextAreaStories.Variants} />

<Subsection title="Sizes">

`sm`, `md`, and `lg`, with Text Area's padding, corners, and text size. `sm` keeps `md`'s corners
and text with tighter padding above and below, as on Text Area.

</Subsection>

<Subsection title="Context">

`context`, as on Text Area: `default` is the bordered field. `inline` has no border or background at
rest; hover shows the hover background and a line along the bottom, and focus and invalid show a
2px line along the bottom. The older `appearance` prop still works: `subtle` and `inline` map to
`context="inline"`.

</Subsection>

<Section title="Behavior">

<Subsection title="Linking a record">

Typing `/` at the start of the text or after a space starts a link. A `/` anywhere else, as in a
date or a URL, is typed as a slash. The query goes into a small box in the text, and the list under
it shows the matching records, grouped by type. Arrow keys move the highlight, Enter links the
highlighted record as a tag followed by a space, and Escape, a space, or a click outside the field
closes the list and keeps what was typed as plain text.

<Example of={RichTextAreaStories.Playground} caption="Type / to link an account, matter, roadmap, or document. The node array below updates as you edit." />

</Subsection>

<Subsection title="Search and recents">

`onSearch` gets the query and returns groups of records, now or as a promise. When the list first
opens, before anything is typed, it shows `recents` if you pass them, or calls `onSearch('')`.
Typed queries wait 150ms before searching, and an answer to an older query never replaces a newer
one.

</Subsection>

<Subsection title="Tags">

`entityConfig` gives each record type a tag tone and an icon, used for the tag and for its group's
heading in the list. Tags aren't tab stops; a tag with an `href` is a link.
Deleting a tag leaves the space after it.

</Subsection>

<Subsection title="The value">

The value is an array of text runs and records, not HTML or Markdown, so you can store it as it is.
The editor reads `value` once, when it mounts, and leads from then on: `onChange` reports every
edit, and a new `value` passed later is ignored.

<Example of={RichTextAreaStories.Prefilled} caption="Loaded with text and two tags; the node array below shows the round trip." />

</Subsection>

<Subsection title="Height and states">

The editor starts `rows` lines tall, 3 unless you set it, and grows as the text gets longer, with
no limit. Dragging the resize handle, vertical by default, sets a fixed height, and the text
scrolls from there. `invalid` shows Text Area's error border, and it stays while the editor has
focus. `disabled` turns off editing.

<Example of={RichTextAreaStories.States} />

</Subsection>

<Subsection title="Known limits">

Rich Text Area is in beta. The `/` query box is checked in Chrome; in Firefox and Safari the caret
can slip out of it. Backspace doesn't remove a tag as one unit in every position, and pasted rich
text isn't cleaned into the value. The list isn't announced to screen readers yet (see
Accessibility).

</Subsection>

</Section>

<Section title="Accessibility">

- The editor is a `div` with `role="textbox"`, `aria-multiline="true"`, and `contenteditable`, in the
  tab order. It isn't a native control, so it has no form `name` and isn't sent with a form.
- Name it with `aria-label`, or `aria-labelledby` pointing at a visible label. A `label` with
  `htmlFor` doesn't name it, because a label can only point at a native control. Field names it by
  `aria-labelledby`, and passes its message, error, and `required` (as `aria-required`).
- `invalid` sets `aria-invalid` on the editor.
- `disabled` turns off editing, takes the editor out of the tab order, and sets `aria-disabled`.
- The editor has `aria-haspopup="menu"`. While the list is open, focus stays in the editor so typing
  keeps reaching the query; `aria-controls` names the list, and `aria-activedescendant` points at
  the highlighted record, so a screen reader follows the highlight.
- Tags aren't tab stops. A tag with an `href` is a link.

<Keyboard>
  <Key keys="/">At the start of the text or after a space, starts a link and opens the list. Anywhere else, types a slash.</Key>
  <Key keys="ArrowDown">With the list open, moves the highlight down, stopping at the last record.</Key>
  <Key keys="ArrowUp">With the list open, moves the highlight up, stopping at the first record.</Key>
  <Key keys="Enter">With the list open, links the highlighted record as a tag followed by a space. Otherwise starts a new line.</Key>
  <Key keys="Escape">With the list open, closes it and keeps what was typed as plain text.</Key>
  <Key keys="Tab">With the list open, closes it and moves focus on, keeping what was typed as text.</Key>
  <Key keys="Space">While typing a query, ends the link and closes the list; what was typed stays as text.</Key>
  <Key keys="Tab">Moves focus to the editor and out of it. A disabled editor is skipped.</Key>
</Keyboard>

<Section title="API">

`value` is an array of `{ type: 'text', text }` and `{ type: 'entity', entity }` nodes, where an
entity is `{ id, entityType, label, href? }`. `onSearch` and `recents` use groups of
`{ id, heading, entityType, items }`, where each item is
`{ id, entityType, label, description?, href?, leadingElement? }`. A `leadingElement` that's an
Avatar or Avatar Group sits beside the label with no description line.
