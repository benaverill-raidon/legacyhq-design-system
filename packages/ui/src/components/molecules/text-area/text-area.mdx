# Text Area

Text Area is the multi-line counterpart of Text Field: a real native `<textarea>` in the same bordered
frame, for writing or editing content that spans several lines — notes, descriptions, comments. It
shares Text Field's size, appearance, invalid, and state treatment token-for-token. The frame styling
lives on a wrapper `<div>` (the same pattern Text Field uses) so it can host an optional trailing
icon/action slot (`iconAfter`).

<Canvas of={TextAreaStories.Playground} />

## When to use

- Any genuinely multi-line free text — notes, descriptions, comments, message bodies.
- Set `rows` for a fixed initial height, or opt into `autoResize` to grow with content.

## When not to use

- **A single-line value.** Use Text Field.
- **A value chosen from a fixed set of options.** Use Select.
- **Inline entity tags / formatting.** Not supported yet — Figma's `type=rich-inline` (a
  slash-command entity-tagging mode) is unimplemented; see "Not built yet" below.

## Sizes and appearance

<Canvas of={TextAreaStories.Variants} />

`appearance="default"` is the standard bordered box, rounded on all four corners — correct for nearly
every case. `appearance="subtle"` has no visible border or background until it's hovered, focused, or
invalid — only a bottom accent line reveals, and its bottom corners stay square. Figma names this axis
`tone`; the code uses `appearance`, the same name and axis as its Text Field sibling. Sizes match Text
Field (`body-md` at sm/md, `body-lg` at lg; radius steps up to `xl` at lg). The compact `sm` option
supports small editable key/value rows.

## States

Hover and focus below are pinned via `data-force-state` (documentation-only); invalid and disabled are
real props.

<Canvas of={TextAreaStories.States} />

Figma models `hover`/`focus`/`typing`/`filled`/`autofill` as if they were variants to pick between.
They aren't real props — they fall out of native `:hover`/`:focus` and the textarea's own
placeholder/value. `invalid` is the one real boolean among them. Focus and invalid replace the border
color and paint the thicker (2px) edge with an inset `box-shadow` rather than a real `border-width`
change, so the multi-line text never shifts by a pixel. Hover is suppressed once the field is focused.

## Resizing

<Canvas of={TextAreaStories.Resize} />

`resize` maps to the CSS `resize` property, defaulting to `vertical` — content can grow downward
without a drag breaking the surrounding layout. Use `none` to lock the height for a fixed layout;
content still scrolls natively. A disabled field cannot be resized.

<Canvas of={TextAreaStories.AutoResize} />

`autoResize` is opt-in. It starts at the matching TextField control height (sm/md/lg), grows with
existing or entered content, and shrinks when text is removed. `maxRows` defaults to six visible
lines, after which the textarea scrolls vertically. This mode overrides `rows` and manual resizing.
It also recalculates when the field width changes, so wrapped text fits its container.

For editable key/value rows, compose `<TextArea autoResize size={size} appearance="inline" />`
inside `<InlineEdit actionPlacement="end" actionAlignment="start">`. The row grows in normal flow;
allow space to its trailing side for the actions. Enter inserts a newline, Ctrl/Cmd+Enter confirms,
and Escape cancels.

## Content

<Canvas of={TextAreaStories.Content} />

Text Area has no label of its own — pair it with a native `<label htmlFor>` pointing at its `id`, or
pass `aria-label`. There is no built-in character-count or helper chrome; compose those around it, as
the counted example shows.

## Trailing icon

<Canvas of={TextAreaStories.IconAfter} />

`iconAfter` places an icon or interactive control (like an edit IconButton) at the trailing end of the
frame. The slot is not `aria-hidden` — it may hold a real focusable action. The `inline` appearance
combined with `iconAfter` is the standard pattern for embedding inside a Key Value Pair.

## Do / Don't

**Do** pair Text Area with a real label and a sensible `rows`.

```tsx
<label htmlFor="notes">Notes</label>
<TextArea id="notes" rows={4} />
```

**Don't** use it for a single line, or rely on the placeholder as the only accessible name.

```tsx
<TextArea rows={1} placeholder="Name" />
```

## Not built yet: `type=rich-inline` (inline entity tagging)

Figma's second `type`, `rich-inline`, is an **inline entity-tagging** mode — not rich-text
formatting. While typing, a user presses **`/`** to open a searchable, grouped dropdown of entities to
link, and each choice is inserted inline as a **navigational tag** — a colored, icon-bearing chip that
links to that entity. It looks identical to `default` in the static mockup; the whole difference is
behavior.

It's deferred to a dedicated pass because it's a real feature, not a variant: it needs a
slash-triggered searchable **Dropdown Menu** (grouped sections), a new **navigational-tag** element
(which doesn't exist yet), and an editable surface that mixes text and tags (`contenteditable`, not a
plain `<textarea>`). Because none of that ships today, no `type` prop is exposed.

## Related components

- **Text Field** — single-line free text; shares the frame token-for-token.
- **Select** — for choosing from a fixed set of options instead of typing free text.
- **Label** — for a trailing unit/status pill (as Text Field uses).
- **Key Value Pair** — embeds Text Area with `appearance="inline"` and `iconAfter` for inline editing.
