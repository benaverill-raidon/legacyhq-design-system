<Section title="Variants">

`tone` sets the bar's color and its icon: `default` is a dark taupe bar with a dot, `warning` an
orange bar with dark text and the warning icon, and `error` a red bar with the error icon. The text,
icon, and dot share one color per tone. `appearance`, the earlier name for `tone`, is still accepted.

<Example of={BannerStories.Tones} />

<Subsection title="Actions on the bar">

Banner doesn't style its actions, so match them to the bar. On the dark `default` and `error` bars,
set `isInverse` on each Button: no fill, light text, and light hover and press overlays. The
`warning` bar has dark text, so its Buttons use `prominence="primary"` with `tone="warning"` instead.
Keep to one or two actions; Banner is an announcement, not a toolbar.

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="One line">

The message never wraps, so the bar stays one row tall. Text that doesn't fit is cut off with an
ellipsis, and there's no tooltip or other way to see the rest. Lead with what matters and put the
detail behind an action. The actions keep their size; the message gives up the space.

The bar can shrink below its message in any container, a flex row or a grid column included, so a
long message is cut off at the container's edge rather than widening the bar.

<Example of={BannerStories.EdgeCases} caption="A long message cut off at the edge, a bar in a 360px container, and one in a 480px flex row." />

</Subsection>

<Subsection title="Content">

The message is the only required part. `showIcon={false}` removes the icon or dot, but not the
status text read before the message. Without `actions`, the message takes the full width.

<Example of={BannerStories.Content} caption="Message only, no icon, two actions, and a single action on the error bar." />

</Subsection>

<Subsection title="Dismissing">

Banner has no close button and no dismissed state. If people can dismiss it, put a Dismiss Button in
`actions` and stop rendering the Banner from its click handler.

</Subsection>

</Section>

<Section title="Accessibility">

- Banner renders a `div` with `role="status"`, a polite live region: a change to its message while
  it's on the page is read without interrupting. A Banner that's added with its message already in
  it may not be read out as it appears, depending on the screen reader.
- Pass `role="alert"` for an urgent error that must interrupt, or another role when the bar plays a
  different part on the page.
- The icon and dot are hidden from assistive technology. For `warning` and `error`, visually hidden
  text, "Warning:" or "Error:", is read before the message, so the meaning doesn't depend on color.
  `default` reads none. Translate it with `statusLabel`.
- The full message is in the page even when it's cut off, so screen readers read all of it, but
  sighted users only see what fits.
- The bar isn't focusable. Its actions are reached with Tab, in page order.

</Section>
