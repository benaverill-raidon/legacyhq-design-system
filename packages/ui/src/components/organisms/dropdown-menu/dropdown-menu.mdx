export const matterActions = (close) => [
  {
    id: 'actions',
    items: [
      { id: 'rename', label: 'Rename', leadingElement: <EditIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'duplicate', label: 'Duplicate', leadingElement: <CopyIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'archive', label: 'Archive', leadingElement: <ArchiveIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'delete', label: 'Delete', leadingElement: <DeleteIcon spacing="spacious" decorative />, onSelect: close },
    ],
  },
];

export const ActionsDropdown = ({ showSearch = false }) => {
  const [open, setOpen] = React.useState(false);
  return (
    <DropdownMenu
      aria-label="Matter actions"
      open={open}
      onOpenChange={setOpen}
      showSearch={showSearch}
      searchPlaceholder="Search actions"
      sections={matterActions(() => setOpen(false))}
    >
      <Button iconAfter={<CaretDownIcon />} isExpanded={open} onClick={() => setOpen((current) => !current)}>
        Actions
      </Button>
    </DropdownMenu>
  );
};

export const RowActionsDropdown = () => {
  const [open, setOpen] = React.useState(false);
  return (
    <DropdownMenu aria-label="Row actions" open={open} onOpenChange={setOpen} alignment="end" showSearch={false} sections={matterActions(() => setOpen(false))}>
      <IconButton aria-label="Row actions" appearance="subtle" isExpanded={open} onClick={() => setOpen((current) => !current)}>
        <MoreVertIcon />
      </IconButton>
    </DropdownMenu>
  );
};

<Section title="Variants">

<Subsection title="Alignment">

`alignment` sets which edge of the trigger the panel lines up with: `start`, the default, `center`,
or `end` (Figma's `left`, `center`, and `right`). It always opens below the trigger, as in Figma,
where it fits. Where it doesn't, it moves to the position that overflows the viewport least, trying
the same alignment above first, and it's kept inside the viewport. Placement is left-to-right only:
start is the trigger's left edge even in a right-to-left page. The earlier `left` and `right` are
deprecated and still accepted.

<Example of={DropdownMenuStories.Alignment} caption="Start, center, and end, each open below its trigger." />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Your state opens and closes it">

Dropdown Menu never opens or closes itself. Keep `open` in your state, toggle it from the trigger's
`onClick`, and pass `onOpenChange`. It's called with `false` on Escape, a press outside the trigger
and the panel, Tab out of the panel, and when an item is chosen, after the item's `onSelect`. To keep
the menu open after a choice, such as for a checkbox row, call `event.preventDefault()` in that
`onSelect`. While closed, only the trigger renders.

<Example of={DropdownMenuStories.Playground} caption="Open it, search, and choose an action: choosing closes the menu." />

</Subsection>

<Subsection title="Focus">

Opening the menu moves focus into it: to the search field when there is one, otherwise to the first
enabled row. Choosing an item, Escape, or Tab out of the panel returns focus to the trigger, so the
tab order runs trigger, menu, then the rest of the page, though the panel is added at the end of
the page. If an item's `onSelect` moves focus elsewhere, such as into a dialog it opens, focus stays
there. A trigger with `role="combobox"`, like Select's field, keeps focus while the menu is open,
since typing filters it, and closes the menu itself.

</Subsection>

<Subsection title="Triggers">

Any one element can be the trigger: a Button, an Icon Button, an Avatar, a Tag. It's cloned to add a
ref, for positioning and returning focus, `aria-haspopup="menu"` (unless it sets its own), and
`aria-expanded` and `aria-controls`, so it must pass those on to its DOM element. Button and Icon
Button keep the `aria-expanded` Dropdown Menu adds, and keep their hover fill while it's `true`.

<Example of={DropdownMenuStories.Content} caption="An Icon Button and an Avatar as triggers." />

</Subsection>

<Subsection title="Position and width">

The panel sits 8px below the trigger and stays at least 8px inside the viewport. It moves with the
trigger as the page scrolls or resizes, and hides while the trigger is scrolled out of view. Its
width is the Menu's `size`. `matchTriggerWidth` makes it as wide as the trigger instead, and
`anchorRef` positions it against another element, as Select does with its field frame. Menu's
`fullWidth` makes the panel as wide as its widest row.

</Subsection>

<Subsection title="Several sections">

Menu's sections, headings, and dividers all work inside the panel.

<Example of={DropdownMenuStories.EdgeCases} caption="Two sections with headings, each announced as a group; choosing any row closes the menu." />

</Subsection>

</Section>

<Section title="Accessibility">

- Dropdown Menu adds no element around the trigger, which keeps its own role and name. While open,
  a panel with no role is added at the end of the page, holding a Menu with `role="menu"`. Name it
  with `aria-label` or `aria-labelledby`, which Dropdown Menu passes to the Menu.
- The trigger gets `aria-haspopup="menu"` (unless it sets its own), `aria-expanded`, and
  `aria-controls` pointing at the panel while it's open.
- It follows the menu-button pattern: opening moves focus to the search field, or without one to the
  first enabled row, and choosing an item, Escape, or Tab out of the panel closes it and returns
  focus to the trigger. So the panel's place at the end of the page doesn't put it last in the tab
  order.
- While the menu is open, Escape calls `onOpenChange(false)` wherever focus is.
- Inside the panel, the rows work as Menu's do: one tab stop, and arrow keys between rows. Headed
  sections are groups named by their headings, and the empty message is announced politely.

<Keyboard>
  <Key keys="Enter">On the trigger, runs its `onClick`, which opens the menu and moves focus into it. On a row, chooses it, closes the menu, and returns focus to the trigger.</Key>
  <Key keys="Space">The same as Enter.</Key>
  <Key keys="Tab">With a search field, moves from it to the clear button, then into the rows. From the rows, or Shift+Tab from the search field, closes the menu and returns focus to the trigger.</Key>
  <Key keys="Arrow Down">In the rows, moves to the next enabled row, wrapping from the last to the first.</Key>
  <Key keys="Arrow Up">In the rows, moves to the previous enabled row, wrapping from the first to the last.</Key>
  <Key keys="Home">In the rows, moves to the first enabled row.</Key>
  <Key keys="End">In the rows, moves to the last enabled row.</Key>
  <Key keys="Escape">While the menu is open, calls `onOpenChange(false)`, wherever focus is. From inside the panel, also returns focus to the trigger.</Key>
</Keyboard>

</Section>

<Section title="API">

<PropsTable of={DropdownMenuStories} />

Dropdown Menu's other props are Menu's, passed to the Menu in the panel: `sections`, `size`,
`showSearch`, `searchValue`, `onSearchChange`, `searchPlaceholder`, `searchLabel`,
`clearSearchLabel`, `showScrollbar`, `maxHeight`, `loading`, `loadingLabel`, `emptyMessage`,
`fullWidth`, `aria-label`, and `aria-labelledby`. See <DocLink to="Components/Actions/Menu" /> for
what each does. `matchTriggerWidth` also sets `fullWidth`. Each item's `onSelect` is wrapped so that
choosing it closes the menu.
