export const matterActions = (close) => [
  {
    id: 'actions',
    items: [
      { id: 'rename', label: 'Rename', leadingElement: <EditIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'duplicate', label: 'Duplicate', leadingElement: <CopyIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'archive', label: 'Archive', leadingElement: <ArchiveIcon spacing="spacious" decorative />, onSelect: close },
      { id: 'delete', label: 'Delete', leadingElement: <DeleteIcon spacing="spacious" decorative />, onSelect: close },
    ],
  },
];

export const ActionsDropdown = ({ showSearch = false }) => {
  const [open, setOpen] = React.useState(false);
  return (
    <DropdownMenu
      aria-label="Matter actions"
      open={open}
      onOpenChange={setOpen}
      showSearch={showSearch}
      searchPlaceholder="Search actions"
      sections={matterActions(() => setOpen(false))}
    >
      <Button iconAfter={<CaretDownIcon />} isExpanded={open} onClick={() => setOpen((current) => !current)}>
        Actions
      </Button>
    </DropdownMenu>
  );
};

export const RowActionsDropdown = () => {
  const [open, setOpen] = React.useState(false);
  return (
    <DropdownMenu aria-label="Row actions" open={open} onOpenChange={setOpen} alignment="right" showSearch={false} sections={matterActions(() => setOpen(false))}>
      <IconButton aria-label="Row actions" appearance="subtle" isExpanded={open} onClick={() => setOpen((current) => !current)}>
        <MoreVertIcon />
      </IconButton>
    </DropdownMenu>
  );
};

<Section title="Variants">

<Subsection title="Alignment">

`alignment` sets which edge of the trigger the panel lines up with: `left`, the default, `center`,
or `right`. It always opens below the trigger, as in Figma, where it fits. Where it doesn't, it
moves to the position that overflows the viewport least, trying the same alignment above first,
and it's kept inside the viewport.

<Example of={DropdownMenuStories.Alignment} caption="Left, center, and right, each open below its trigger." />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Your state opens and closes it">

Dropdown Menu never opens or closes itself. Keep `open` in your state, toggle it from the trigger's
`onClick`, and pass `onOpenChange`, which is called with `false` on Escape or a press outside the
trigger and the panel. Choosing an item doesn't close the menu, because Menu doesn't know it's in
one: set `open` to false from the item's `onSelect`. While closed, only the trigger renders.

<Example of={DropdownMenuStories.Playground} caption="Open it, search, and choose an action: the item's onSelect closes the menu." />

</Subsection>

<Subsection title="Triggers">

Any one element can be the trigger: a Button, an Icon Button, an Avatar, a Tag. It's cloned to add a
ref, for positioning, and `aria-expanded` and `aria-controls`, so it must pass those on to its DOM
element. On a Button or an Icon Button, also set `isExpanded={open}`: it keeps the hover fill while
the menu is open, and without it, Button drops the `aria-expanded` that Dropdown Menu adds and Icon
Button reports `false`.

<Example of={DropdownMenuStories.Content} caption="An Icon Button and an Avatar as triggers." />

</Subsection>

<Subsection title="Position and width">

The panel sits 8px below the trigger and stays at least 8px inside the viewport. It moves with the
trigger as the page scrolls or resizes, and hides while the trigger is scrolled out of view. Its
width is the Menu's `size`. `matchTriggerWidth` makes it as wide as the trigger instead, and
`anchorRef` positions it against another element, as Select does with its field frame.

</Subsection>

<Subsection title="Several sections">

Menu's sections, headings, and dividers all work inside the panel.

<Example of={DropdownMenuStories.EdgeCases} caption="Two sections with headings; choosing any row closes the menu." />

</Subsection>

</Section>

<Section title="Accessibility">

- Dropdown Menu adds no element around the trigger, which keeps its own role and name. While open,
  a panel with no role is added at the end of the page, holding a Menu with `role="menu"`. Name it
  with `aria-label` or `aria-labelledby`, which Dropdown Menu passes to the Menu.
- The trigger gets `aria-expanded`, and `aria-controls` pointing at the panel while it's open. On a
  Button or an Icon Button, set `isExpanded={open}` too, so the state is announced. Dropdown Menu
  doesn't set `aria-haspopup`; set `aria-haspopup="menu"` on the trigger yourself.
- Opening the menu moves focus only when there's a search field, which takes focus. Without one,
  focus stays on the trigger, and because the panel is at the end of the page, Tab reaches its rows
  only after everything else on the page.
- While the menu is open, Escape calls `onOpenChange(false)` wherever focus is. Focus isn't moved
  back to the trigger, so if it was in the panel, it's left on the page.
- Inside the panel, the rows work as Menu's do: one tab stop, and arrow keys between rows.

<Keyboard>
  <Key keys="Enter">On the trigger, runs its `onClick`, which opens or closes the menu.</Key>
  <Key keys="Space">On the trigger, the same as Enter.</Key>
  <Key keys="Tab">With a search field, moves from it to the clear button, then into the rows. Without one, moves from the trigger to the next control on the page.</Key>
  <Key keys="Arrow Down">In the rows, moves to the next enabled row, wrapping from the last to the first.</Key>
  <Key keys="Arrow Up">In the rows, moves to the previous enabled row, wrapping from the first to the last.</Key>
  <Key keys="Home">In the rows, moves to the first enabled row.</Key>
  <Key keys="End">In the rows, moves to the last enabled row.</Key>
  <Key keys="Escape">While the menu is open, calls `onOpenChange(false)`, wherever focus is.</Key>
</Keyboard>

</Section>

<Section title="API">

<PropsTable of={DropdownMenuStories} />

Dropdown Menu's other props are Menu's, passed to the Menu in the panel: `sections`, `size`,
`showSearch`, `searchValue`, `onSearchChange`, `searchPlaceholder`, `showScrollbar`, `maxHeight`,
`loading`, `loadingLabel`, `emptyMessage`, `aria-label`, and `aria-labelledby`. See
<DocLink to="Components/Actions/Menu" /> for what each does. Two Menu props are accepted but not
passed on: `clearSearchLabel`, so the clear button is always named "Clear search", and `fullWidth`,
which `matchTriggerWidth` sets instead.
