<Section title="Behavior">

<Subsection title="Header">

`title` and `description` make the header, and `requiredLegend` adds the line "\* indicates a
required field", with the `*` in the error color to match Field's required mark. Set it when any
field is required. Without all three, there's no header.

<Example of={FormStories.Playground} />

</Subsection>

<Subsection title="Sections">

A FormSection groups related fields and puts space above them, so it separates them from the header
or the section before. Its `title` is optional. Put Fields straight in a section to stack them one per
line, at the full width.

<Example of={FormStories.Sections} />

</Subsection>

<Subsection title="Rows">

A FormRow puts its fields side by side in equal columns. Figma designs rows of up to four. A row
stays on one line at every width: it doesn't stack on a narrow screen, so keep rows to short fields
that fit.

<Example of={FormStories.Rows} />

</Subsection>

<Subsection title="Footer">

A FormFooter holds the actions, with more space above it than between sections. `align="end"`, the
default, puts them at the end of the line; `align="start"` puts them at the start. It spaces its
Buttons the way Button Group does, so put the Buttons straight in it.

<Example of={FormStories.FooterAlignment} />

</Subsection>

<Subsection title="Submitting">

Form keeps no state of its own. It's a native `form`, so `onSubmit` fires when someone presses a
`type="submit"` Button, or Enter in a single-line field, and the browser checks `required` and other
constraints first unless you set `noValidate`. Each field's value, error, and message are yours,
through Field.

<Example of={FormStories.EdgeCases} caption="Edge cases: a form with no header, and a form on a dark surface." />

</Subsection>

<Subsection title="Disabling a group of fields">

To disable several fields at once, put them in a native `fieldset` with `disabled`. Every form
control in the system follows it as it follows its own `disabled`: it looks disabled, leaves the tab
order, and can't be changed or opened. A FormSection is a `div`, so put the `fieldset` inside it,
and clear the browser's own border, padding, and margin. Field's label doesn't dim, with a fieldset
or the control's own `disabled`.

<Example of={FormStories.DisabledFieldset} caption="A closed matter's details, locked by a disabled fieldset until the matter is reopened." />

</Subsection>

<Subsection title="When errors show">

Form doesn't check anything itself, but when its errors show follows one rule across the system:

1. **Check when the form is submitted**, not while someone is still typing.
2. **Show every error at once**: a Section Message with `tone="error"` at the top of the form,
   naming each field that needs fixing and linking to it, and each field's own error through Field.
   Move focus to the summary.
3. **Then update each field's error as its value changes**, so it clears as soon as it's fixed. The
   summary is a live region, so it changes only on the next submit.

Set `noValidate` when you show the system's errors, so the browser's own messages don't come first.
<DocLink to="Patterns/Forms and Validation" /> builds the whole flow.

</Subsection>

<Section title="Accessibility">

- Form renders a native `form`, so submitting with Enter or a submit button, and the browser's own
  checks, work with no extra code.
- A form is announced as a form landmark only when it has a name, and `title` doesn't give it one.
  Pass `aria-label` or `aria-labelledby` if people should find the form by landmark.
- The title and the section titles are text in a `div`, not headings, so they aren't in the page's
  heading outline. Put the page's own heading above the form when it needs one. A FormSection is a
  `div`, not a `fieldset`, so its title isn't announced with the fields in it.
- The required legend is read as text, `*` included. Field hides its own `*` from assistive
  technology and sets the control's native `required` instead.
- Each field's name, description, and error come from Field. Form doesn't change them.
- Errors show on submit, all at once, so nobody is interrupted while typing. Form doesn't move focus
  when a submit fails: move it to the summary at the top, which links to each field.

Form adds no keys of its own; the browser handles moving through fields and submitting.

<Keyboard>
  <Key keys="Tab">Moves through the fields and the footer's buttons, in the order they're written.</Key>
  <Key keys="Enter">In a single-line field, submits the form, as the browser does when the form has a submit button.</Key>
</Keyboard>
