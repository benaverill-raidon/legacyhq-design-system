export const DialogExample = ({ trigger, tone = 'default', title, label, body, confirm, width = 'sm', onExpand }) => {
  const [open, setOpen] = React.useState(false);
  const close = () => setOpen(false);
  return (
    <>
      <Button prominence={tone === 'error' ? 'secondary' : 'primary'} tone={tone === 'error' ? 'error' : 'default'} onClick={() => setOpen(true)}>
        {trigger}
      </Button>
      <ModalDialog
        open={open}
        onClose={close}
        title={title}
        aria-label={label}
        tone={tone}
        width={width}
        onExpand={onExpand}
        footer={
          <ButtonGroup>
            <Button prominence="tertiary" onClick={close}>
              Cancel
            </Button>
            <Button prominence="primary" tone={tone} onClick={close}>
              {confirm}
            </Button>
          </ButtonGroup>
        }
      >
        {body}
      </ModalDialog>
    </>
  );
};

<Section title="Variants">

<Subsection title="Tone">

`tone` says what the decision means. `warning` and `error` put a status icon before the title;
`default` shows none. Tone doesn't touch the footer, so give the Confirm button the same `tone`: an
error dialog confirms with `<Button prominence="primary" tone="error">`.

<Example of={ModalDialogStories.Tones} caption="Default, warning, and error dialogs, each with a matching Confirm button." />

</Subsection>

<Subsection title="Widths">

Four panel widths: `sm` (400px), `md` (600px, the default), `lg` (752px), and `xl` (968px). On a
narrow window the panel narrows to fit inside the backdrop's 40px inset. Use `sm` for a short
confirmation and the wider sizes for a form or a preview.

<Example of={ModalDialogStories.Widths} />

</Subsection>

</Section>

<Section title="Behavior">

<Subsection title="Your state opens and closes it">

Modal Dialog never closes itself. Keep `open` in your state and set it to `false` in `onClose`,
which is called by the Close button, by Escape, and by a press that starts and ends on the backdrop.
A text selection dragged out of the panel doesn't close it. Turn off Escape or the backdrop with
`closeOnEscape` or `closeOnBackdropClick`; since `onClose` comes before any change, you can also ask
before discarding work. While closed, it renders nothing.

<Example of={ModalDialogStories.DestructiveConfirmation} caption="A destructive confirmation: the error tone, a narrow panel, and an error Confirm button." />

</Subsection>

<Subsection title="Focus">

When the dialog opens, focus moves to the panel, or to the element in `initialFocusRef`, such as the
first field of a form. Tab and Shift+Tab cycle through the dialog's controls and don't leave it.
When it closes, focus goes back to the element that had it before, usually the button that opened
it.

</Subsection>

<Subsection title="Scrolling">

While the dialog is open, the page behind it doesn't scroll. A long body scrolls inside the panel,
with the header and footer in place.

<Example of={ModalDialogStories.ScrollingBody} caption="Twenty paragraphs of terms scroll inside the panel." />

</Subsection>

<Subsection title="Header actions">

The header ends with a Close button unless you set `showCloseButton={false}`. Pass `onExpand` to
add an Expand button before it, for a preview that can open at full size; Modal Dialog shows the
button and calls `onExpand`, and what expanding does is up to you.

<Example of={ModalDialogStories.HeaderExpand} />

</Subsection>

<Subsection title="Without a title or a footer">

Leave out `footer` for a dialog that only informs; people close it with the Close button or
Escape. Without a visible `title`, name the dialog with `aria-label`; in development, a dialog with
neither logs a warning. The header still shows while it holds the Close button.

<Example of={ModalDialogStories.EdgeCases} />

</Subsection>

<Subsection title="Layering and motion">

Tooltip, Dropdown Menu, the pickers, and Inline Message open in a Popup, which sits above the
dialog, so they show over it, including the tooltips of its own Close and Expand buttons. A dialog
opened from inside another shows over the first. The order (dialog, then toast, then popup) is kept
in one place, `primitives/layers.ts`.

Escape closes only the topmost layer: an open menu, picker, or tooltip in the dialog closes first,
and the next Escape closes the dialog; with two dialogs open, only the top one closes. A control
inside that handles Escape itself, such as Inline Message's popup, keeps it.

The backdrop fades in and the panel fades in while rising 8px, both with `fade-quick`; with
reduced motion, the dialog appears at once. It leaves at once when it closes.

</Subsection>

<Section title="Accessibility">

- The panel has `role="dialog"` and `aria-modal="true"`. It's named by its `title`, through
  `aria-labelledby`, or by `aria-label` when there's no title; with neither, it has no name, and
  it warns in development.
- Opening moves focus into the dialog, Tab and Shift+Tab stay inside it, and closing returns focus
  to the element that had it before. The panel itself can take focus, so focus stays in the dialog
  even when it holds no controls.
- The page behind isn't made inert: `aria-modal` tells assistive technology to stay in the dialog,
  and the backdrop stops pointer presses from reaching the page.
- The status icon is hidden from assistive technology, so the title and the buttons have to carry
  the meaning on their own.
- The Close and Expand buttons are named by `closeLabel` and `expandLabel`, "Close" and "Expand" by
  default; translate them with the rest of your text.

<Keyboard>
  <Key keys="Tab">Moves to the next control in the dialog, and from the last back to the first.</Key>
  <Key keys="Shift + Tab">Moves to the previous control, and from the first, or the panel, to the last.</Key>
  <Key keys="Escape">Calls `onClose`, unless `closeOnEscape` is `false`, when nothing opened above the dialog (a menu, a tooltip, another dialog) is still open: that closes first.</Key>
</Keyboard>
