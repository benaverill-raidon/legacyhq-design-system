# Modal Dialog

Modal Dialog is an organism that interrupts the flow to focus the user on a single task or decision -
a confirmation, a short form, a piece of content that needs acknowledgement. It renders a backdrop
over the page and a centered panel with a header (title + close), a scrollable body, and a footer for
the actions, and it handles the modal behaviour: it portals above the page, traps focus, closes on
Escape or a backdrop click, locks page scroll, and restores focus to whatever opened it.

## When to use

- A decision or confirmation the user must resolve before continuing (especially a destructive one).
- A short, focused task or a piece of content that needs to be acknowledged.

## When not to use

- **Non-blocking, transient feedback.** Use Toast.
- **Contextual overflow anchored to a control** (a menu, a popover). Use Dropdown Menu / Menu.
- **A large or multi-step flow.** Prefer a full page - a modal is for one focused task.

## Anatomy and behaviour

Modal Dialog is controlled: pass `open` and an `onClose`. It never closes itself - `onClose` fires
(from the close button, Escape, or a backdrop click) and the consumer sets `open` to false. While
open it:

- portals into `document.body`, above the page, over a blanket backdrop;
- sets `role="dialog"` + `aria-modal="true"`, named by the `title` (`aria-labelledby`) or, without
  one, by `aria-label`;
- moves focus into the panel, traps Tab within it, and restores focus to the trigger on close;
- locks page scroll; the body scrolls internally when it is taller than the viewport allows.

## Appearance

<Canvas of={ModalDialogStories.Appearances} />

`appearance` (`default` / `warning` / `error`) prepends a status icon to the title in the matching
colour. It deliberately does **not** tone the footer buttons - Modal Dialog can't know your action
layout - so pair `appearance="error"` with a matching Confirm button, e.g.
`<Button appearance="primary" tone="error">Delete</Button>`.

<Canvas of={ModalDialogStories.DestructiveConfirmation} />

## Widths

<Canvas of={ModalDialogStories.Widths} />

Four widths - `small` (400px), `medium` (600px, default), `large` (752px), `extraLarge` (968px). The
panel shrinks to fit narrow viewports (it never exceeds the available width).

## Content

<Canvas of={ModalDialogStories.ScrollingBody} />

The header and footer stay fixed while a long body scrolls. The footer is a slot - pass the actions
(typically a Cancel and a Confirm Button); they render right-aligned. Omit `footer` for an
informational dialog.

<Canvas of={ModalDialogStories.EdgeCases} />

## Accessibility

- Always give the dialog an accessible name: a `title`, or `aria-label` when there's no visible
  title.
- Focus moves into the dialog on open and returns to the trigger on close; Tab is trapped inside.
- Escape closes the dialog (`closeOnEscape`, default on); the close button is labelled "Close" by
  default (`closeLabel`).
- The status icon is decorative - the appearance's meaning is carried by the title text and the
  actions, not the icon alone.

## Related components

- **Button** - the footer actions.
- **Toast** - for non-blocking, transient feedback instead of a blocking dialog.
- **Dropdown Menu / Menu** - for contextual overflow anchored to a control.
