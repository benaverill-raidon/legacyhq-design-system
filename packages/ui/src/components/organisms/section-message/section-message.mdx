# Section Message

Section Message is a bordered, rounded status panel placed inside the flow of a page or a section of
one. It carries a status - information, success, warning, or error - with an optional title, a
description, optional inline actions, and an optional dismiss button.

<Canvas of={SectionMessageStories.Playground} />

## When to use

- A contained, in-context status message inside a section, form, or panel.
- Communicating the result or constraint of the surrounding content - a permission restriction, a
  validation summary, a success confirmation, a warning about the section.
- A message that should sit in the page flow rather than float or span the full width.

## When not to use

- **For a full-width, page-level announcement bar.** Use `Banner`.
- **For a transient, auto-dismissing notification.** Use `Toast`.
- **For an inline status next to a single field or row.** Use `InlineMessage`.
- **For a blocking confirmation or decision.** Use `ModalDialog`.

## Anatomy

<Canvas of={SectionMessageStories.Content} />

1. **Root** - a bordered, rounded box with the appearance's tinted background and colored border.
2. **Icon** - the status icon for the appearance, in its status color. Decorative (`aria-hidden`).
3. **Title** - an optional bold lead line (`heading-sm`).
4. **Description** - the `children`. Wraps to as many lines as needed.
5. **Actions** - optional `Link`s; Section Message inserts a middot separator between them.
6. **Dismiss** - an optional dismiss button (`isDismissible`) in the top-right.

## Usage guidance

### Appearance

`appearance` (`information`, `success`, `warning`, `error`) sets the tinted background, the border
color, and the status icon together - the appearance is the semantic signal. The title and
description always use the default content color; only the icon and border take the status color.

<Canvas of={SectionMessageStories.Appearances} />

### Title and description

The `title` is optional - omit it for a description-only message. The description (`children`) is
required and wraps freely, so Section Message suits longer, multi-line explanations (unlike `Banner`,
whose single line truncates).

### Actions

Pass `Link`s to `actions`; Section Message inserts the `·` separators between them, so callers write
bare Links (a fragment or an array) rather than repeating separator markup. Keep actions to a small
number of related links.

### Dismiss

Set `isDismissible` to show a dismiss button in the top-right. Clicking it hides the message and
calls `onDismiss`. Reserve dismiss for messages the user can safely make go away - not for a
persistent constraint they need to keep seeing.

### Accessibility

Section Message renders with `role="status"` (a polite live region) by default, so one that appears
dynamically is announced without interrupting. Override `role` when the semantics differ - use
`role="alert"` for an urgent error. The status icon is decorative (`aria-hidden`); the meaning is
carried by the title and description text, not by color alone. The dismiss button is a labelled
`IconButton` ("Dismiss").
