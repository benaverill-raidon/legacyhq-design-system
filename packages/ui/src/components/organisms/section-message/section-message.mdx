- A warning about the content beside it, such as an incomplete filing.
- A summary of errors at the top of a form, with `errors` linking to each field that needs fixing.
- The result of an action that changed this section, when it needs explaining.

<Section title="Variants">

`tone` sets the border, the background tint, and the icon together: `information`, `success`,
`warning`, or `error`. Only the border and the icon take the tone's color; the title and description
stay in the default text color. `appearance`, the earlier name for `tone`, is still accepted.

<Section title="Behavior">

<Subsection title="Content">

The description is the only required part. Leave out `title` for a short message, and `actions` when
there's nothing to do. Two or more actions go in a Button Group, which lays them out in a row; a single
Link Button can be passed on its own. Section Message adds no separators between them.

<Example of={SectionMessageStories.Content} caption="Title, description, and actions; description only; a single action; and dismissible." />

</Subsection>

<Subsection title="Listing errors">

`errors` turns the message into the summary at the top of a form after a failed submit. Each entry
names a field (`label`), says what to do there (`message`, optional), and points at its control by
`targetId`. They're listed under the description, in the order you pass them, which should be the
order of the form. The description is optional here: a title that counts the fields and the list
often say enough.

Each label is a Link to `#` and the control's id. Following it moves focus to the control, which
then reads its own label and error; when the target can't take focus, such as a Radio Group's
fieldset, its first control gets focus. Section Message doesn't check anything or move focus to
itself: after a failed submit, move focus to the message (it takes a `ref` and `tabIndex={-1}`), and
change `errors` only on the next submit. <DocLink to="Patterns/Forms and Validation" /> builds the
whole flow.

<Example of={SectionMessageStories.ErrorSummary} caption="A form's summary: two fields, each a link that moves focus to it. Billing points at a Radio Group, so focus goes to its first radio." />

</Subsection>

<Subsection title="Dismissing">

`isDismissible` adds a dismiss button. Clicking it hides the message and calls `onDismiss`. Section
Message keeps that state itself: it stays hidden until it's unmounted, and there's no prop to show it
again. To bring it back later, render it again with a new `key`. Don't make a restriction or a
warning that still applies dismissible.

<Example of={SectionMessageStories.EdgeCases} caption="A title and description that wrap, with actions and a dismiss button; and a message with no title." />

</Subsection>

<Section title="Accessibility">

- Section Message renders a `div` with `role="status"`, a polite live region: a change to its
  content while it's on the page is read without interrupting. A message that's added with its
  content already in it may not be read out as it appears, depending on the screen reader. Pass
  `role="alert"` for an urgent error that must interrupt.
- The icon is hidden from assistive technology. Visually hidden text with the tone's name, such as
  "Warning:", is read before the title, so the meaning doesn't depend on color. Translate it with
  `statusLabel`.
- The title is styled text in a `div`, not a heading, so it isn't listed among the page's headings.
- `errors` is a `ul`, so it's announced as a list with its count. Each label is a link to `#` and the
  control's id; following it moves focus to the control (or the first control inside it), so the
  field reads its label and its error. The link's own jump is stopped, so the URL doesn't change.
- Section Message doesn't move focus to itself. After a failed submit, move focus to the summary:
  pass a `ref` and `tabIndex={-1}`. A message added with its content already in it may not be read
  out as it appears, so don't rely on the live region for that.
- The dismiss button is an Icon Button named by `dismissLabel`, "Dismiss" by default, which also
  shows as its tooltip on hover and focus.
- Dismissing removes the message, including the button that had focus, and Section Message doesn't
  move focus anywhere. If you need focus to land somewhere specific, move it in `onDismiss`.

<Keyboard>
  <Key keys="Tab">Moves to each error's link, then each action, then the dismiss button.</Key>
  <Key keys="Enter">On an error's link, moves focus to its field. On the dismiss button, hides the message. On an action, follows the link.</Key>
  <Key keys="Space">On the dismiss button, hides the message.</Key>
</Keyboard>
