<Section title="Behavior">

<Subsection title="Columns and cells">

Each column is a `TableColumn` (listed under API). A cell shows `row[key]` as text unless the column
has a `render`, which can return any content: a Link, Tag, Badge, Avatar, Switch, or Buttons. Table
has no cell types of its own.

Mark the column that identifies the row with `emphasis: 'strong'`, which sets it at the heading
weight, and use a strong Link if it opens the record. Align numbers and dates to the end with
`align: 'end'`. `width` and `minWidth` size a column; otherwise columns size to their content and the
table fills its container, scrolling sideways when the columns don't fit.

<Example of={TableStories.Basic} />

<Example of={TableStories.CellVariants} caption="Cell content composed with render, at both sizes." />

</Subsection>

<Subsection title="Header and toolbar">

`title` and `description` sit above the table. `title` is an `h2`; set `headingLevel` to fit it into
the page's outline. The toolbar's first row is a button group at the end: the search, then
`toolbarActions`, such as filter and settings Icon Buttons, then `actions`, such as a primary Button.

`searchable` shows a search Icon Button. Pressing it opens a 280px search field and focuses it; the
field stays open while it has text, shows a clear button then, and closes again if it loses focus
while empty. Table doesn't filter anything: filter `data` in `onSearchChange`. Table keeps the text
itself (start it with `defaultSearchValue`), or control it with `searchValue`.

The second row holds `activeFilters`, the filter Chips you render and control, and a Clear filters
button when you pass `onClearFilters`. Pass `toolbar` to replace both rows with your own.

<Example of={TableStories.WithToolbar} caption="A title, search, filter and settings buttons, and active filter Chips." />

</Subsection>

<Subsection title="Sorting">

Set `sortable` on a column to make its header a button with a sort arrow. Pressing it sorts
ascending, then descending, then back to the order of `data`; pressing another column's header
starts that column at ascending. Every sortable column shows its arrow, which darkens on the sorted
column and points up while it's ascending.

Table sorts `data` itself, by the column's `sortValue` or else `row[key]`: numbers as numbers, text
without regard to case and with numbers inside it in order, and empty values last when ascending.
Start with `defaultSort`, or control it with `sort` and `onSortChange`. With `manualSort`, Table shows
the sort and calls `onSortChange`, and leaves `data` in the order you pass, for sorting on the server.

<Example of={TableStories.Sortable} />

</Subsection>

<Subsection title="Selection">

`selectable` adds a column of Checkboxes. The select-all Checkbox in the header selects or clears
every row on the current page, and shows its indeterminate state when only some of them are
selected. Rows are selected only through their Checkboxes: clicking a row does nothing, so links and
buttons in it work on their own.

While any row is selected, the selection bar takes the place of the toolbar's buttons, with the
count on the left and your `bulkActions` on the right. A selected row takes a brand tint. Selection
is kept by row id, across pages and sorts. The default id is the row's position in `data`, so pass a
`getRowId` that returns a real id. Start with
`defaultSelectedIds`, or control it with `selectedIds` and `onSelectionChange`.

<Example of={TableStories.Selectable} />

<Example of={TableStories.FullShell} caption="Header, toolbar, selection with bulk actions, sorting, and pagination together." />

</Subsection>

<Subsection title="Pagination">

Pass `pageSize` and Table shows that many rows per page and keeps the current page; control the page
with `page` and `onPageChange`. To page on the server, set `manualPagination` with `pageCount`,
`page`, and `onPageChange`, and pass only the current page's rows.

The footer appears when there's more than one page, or when you pass `itemsPerPageOptions`, so a
page size that fits every row doesn't take the page-size Select away. It has the page-size Select
(Table calls `onPageSizeChange` and leaves `pageSize` to you), the range of rows shown, a page Select,
the page count, and previous and next buttons, which are disabled on the first and last pages.

The range runs from the page's first row to its last, such as "11–20 of 42 items". With
`manualPagination`, pass `pageSize` and `totalItems` so Table can place the page; without `pageSize`,
the rows you pass count as one page.

Every piece of footer text is a prop with an English default, for translation: `itemsPerPageLabel`
(shown as given, so include its colon), `getRangeLabel`, `pageLabel`, `getPageCountLabel`,
`previousPageLabel`, `nextPageLabel`, and `paginationLabel`, the footer's accessible name.

<Example of={TableStories.Pagination} />

</Subsection>

<Subsection title="Resizing columns">

Columns can be resized by default. Drag the divider at a header's trailing edge, or focus it and press
Arrow Left or Arrow Right to narrow or widen the column by 16px, from 64px up to the width of the
table's scroll region. The first
resize, or the first selection, fixes every column at its current width, so changing one doesn't
reflow the others and the widths hold as you page. Widths aren't saved, and reset when the table
remounts. Turn resizing off with `resizableColumns={false}`, or for one column with
`resizable: false`.

</Subsection>

<Subsection title="Editable cells">

Set `cellAppearance: 'editable'` on a column and return its editor from `render`: an
<DocLink to="Components/Forms/Inline Edit" /> around a <DocLink to="Components/Forms/Text Field" />
for text, or a <DocLink to="Components/Forms/Select" />, <DocLink to="Components/Forms/Date Picker" />,
or <DocLink to="Components/Forms/Time Picker" />. In an editable cell, these controls take the
inline look at the table's size and fill the cell, so don't set their `size` or `context`. Hover shows
a fill and an underline; editing shows the focus underline. Their menus and calendars keep their
usual look, and the same controls elsewhere in the table don't change.

You keep the value: save it in the control's own callback, such as Inline Edit's `onConfirm` or
Select's `onChange`. Give each editor an accessible name that includes its row.

</Subsection>

<Section title="Accessibility">

- Table renders a native `table` with `thead`, `tbody`, and column headers (`th scope="col"`), so
  screen readers can move by row and column and read each cell with its header.
- The table is named by a visually hidden `caption`: `caption`, or `title` when there's no
  `caption`. Always set one. `title` also renders as a heading above the table, at `headingLevel`.
- The table sits in a scroll region (`role="region"`) that can take focus, so people can scroll it
  sideways with the keyboard. It's named by a string `caption` or `title`, or `scrollRegionLabel`
  ("Table") otherwise.
- Each column header is named by its label alone (its `header`, or `headerLabel` when the header
  isn't text), so screen readers read a cell's column as "Name", not the controls inside the header.
- A sortable header holds a button named by the same label, and the header cell sets `aria-sort` to
  `ascending`, `descending`, or `none`, which screen readers announce with the column. The arrow is
  hidden from assistive technology.
- Selection uses Checkboxes: "Select all rows" (`selectionColumnLabel`) in the header, which is
  announced as mixed when only some rows are selected, and one per row named by `getSelectionLabel`.
  Without it, every row's Checkbox is named "Select row", so always pass it.
- When the number of selected rows changes, a polite live region announces the count, such as
  "3 selected" (`selectionCountLabel`). It isn't announced when the table first renders.
- Each resize handle is a focusable `separator`, vertical, named by `getResizeLabel` ("Resize Name").
  It reports the column's width in pixels as `aria-valuenow` from the start, with 64 as
  `aria-valuemin` and the scroll region's width as `aria-valuemax`.
- While loading, the table sets `aria-busy`. The footer is a `navigation` region named by
  `paginationLabel`, and its Selects and Icon Buttons are named by the footer props.
- Content you render in cells keeps its own semantics: name icon-only buttons, and give each
  editable cell's control a name that includes its row.

<Keyboard>
  <Key keys="Tab">Moves through the toolbar's controls, the scroll region, the header row (the select-all Checkbox, then each sort button and resize handle), each row's Checkbox and controls, and the footer's controls.</Key>
  <Key keys="Enter">On a sort button, sorts by that column, moving to the next step: ascending, descending, unsorted. In an Inline Edit cell, confirms the change.</Key>
  <Key keys="Space">On a sort button, sorts like Enter. On a selection Checkbox, selects or clears the row; on the select-all, every row on the page.</Key>
  <Key keys="Arrow Left">On a resize handle, narrows the column by 16px, down to 64px. In the scroll region, scrolls left.</Key>
  <Key keys="Arrow Right">On a resize handle, widens the column by 16px, up to the scroll region's width. In the scroll region, scrolls right.</Key>
  <Key keys="Escape">In an Inline Edit cell, cancels the change.</Key>
</Keyboard>

Tabbing into an Inline Edit cell starts editing, and tabbing away saves a changed value. Select, Date
Picker, and Time Picker cells, and the footer's Selects, keep their own keyboard; see their pages.

</Section>

`className` is added to the root `div`'s classes. Table passes no other attributes to it.

<Subsection title="Columns">

Each item in `columns` is a `TableColumn<Row>`:

<CodeSample code={`{
    key: string;                        // required; also the default value, row[key]
    header: React.ReactNode;            // required
    render?: (row, rowIndex) => React.ReactNode;   // defaults to String(row[key])
    sortable?: boolean;                 // makes the header a sort button
    sortValue?: (row) => string | number | boolean | null | undefined;   // what the built-in sort compares
    align?: 'start' | 'center' | 'end'; // default 'start'; 'end' for numbers and dates
    emphasis?: 'strong' | 'default';    // 'strong' for the column that identifies the row
    width?: number | string;            // a number is px
    minWidth?: number | string;         // a number is px
    resizable?: boolean;                // default true; false keeps this column's width
    cellAppearance?: 'default' | 'editable';       // 'editable' for an editor returned by render
    headerLabel?: string;               // names the column when header isn't text
    className?: string;                 // added to the column's td cells
    headerClassName?: string;           // added to its th
}`} />

`sort`, `defaultSort`, and `onSortChange` use a `TableSort`, and selection uses row ids
(`string | number`):

<CodeSample code={`{ columnKey: string; direction: 'asc' | 'desc' }`} />

</Subsection>

<Subsection title="Editable cells">

<CodeSample code={`{
