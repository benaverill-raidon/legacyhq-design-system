# Table

Table is an organism for presenting a large, sortable, filterable set of records - the workhorse of
list/index ("All X") pages. It renders a section header, a filter toolbar, a column-config-driven grid
(sortable headers, a selection column, loading/empty states), and a pagination footer, composing Text
Field, Select, Chip, Checkbox, Button, Skeleton, Empty State, and Pagination.

<Canvas of={TableStories.FullShell} />

## When to use

- A page of records the user scans, sorts, filters, selects, and pages through ("All members").
- A selectable list with bulk actions, or a dense data view (`size="sm"`).
- A server-paged dataset (with `manualSort` + `manualPagination`).

## When not to use

- **A simple key/value layout or short static list.** Use plain markup / a description list.
- **A dashboard of cards.** That's a layout grid, not tabular data.
- **A spreadsheet-style editable grid.** Cell editing / formulas are out of scope.

## Columns and data

<Canvas of={TableStories.Basic} />

Pass `columns` + `data`. A column is `{ key, header, render?, sortable?, align?, width? }`; a cell
shows `String(row[key])` unless you pass `render` to compose any content. Always pass a stable
`getRowId` - it defaults to the row index, which is unstable once rows sort or paginate.

## Sorting

<Canvas of={TableStories.Sortable} />

Sorting is owned by default: set `defaultSort`, click a sortable header to cycle ascending ->
descending -> unsorted, and the data reorders client-side. Control it with `sort` + `onSortChange`, or
set `manualSort` to sort server-side.

## Selection

<Canvas of={TableStories.Selectable} />

`selectable` adds a leading Checkbox column with a header select-all (indeterminate for a partial
selection). Selection is **checkbox-only** - rows are never clickable - and is owned by default,
controllable via `selectedIds` + `onSelectionChange`. When one or more rows are selected, a selection
bar appears at the top of the card with the count on the left and your `bulkActions` on the right; a
selectable row also gets a subtle neutral hover, distinct from the brand-tinted selected state.

## Columns, resizing, and interaction rules

Columns resize by default: drag a header's trailing edge (or focus the handle and use the Arrow
keys); opt out with `resizableColumns={false}` or per column with `column.resizable === false`. Mark
the identifier column with `emphasis: 'strong'` (heading weight) and leave other columns at body
weight. Follow the interaction rules consistently: **checkbox** = selection, **Link** = navigation (a
routable value in a cell, or a strong Link for the identifier), **Button** = an action that changes
state. Controls inside a row act independently.

## Toolbar

<Canvas of={TableStories.WithToolbar} />

`searchable` renders the built-in search; `filters` is a slot for your domain Selects; `onClearFilters`
adds a Clear filters action; `activeFilters` renders removable pills. Pass `toolbar` to replace the
whole built-in toolbar.

`onPageChange` for a server-paged API.

## Accessibility

- It's a real `<table>` - always give it an accessible name via `caption` or `title`.
- Sortable headers set `aria-sort` and wrap the label in a `<button>`; the scrollable grid is a
  keyboard-focusable `role="region"`.
- Selection uses real Checkboxes; keep content you put in cells accessible (label in-cell buttons).

## Related components

- **Pagination** - the footer.
- **Select / Text Field / Chip** - the toolbar (filters, search, active filters).
- **Checkbox** - selection. **Button / Icon Button** - actions.
- **Skeleton** - loading rows. **Empty State** - the empty slot.
