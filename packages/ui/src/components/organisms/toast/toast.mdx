<Section title="When to use">

<Usage>
<UseFor>

- Confirming an action that just finished, such as a save or an archive.
- A result from work in the background, such as an upload that finished or failed.
- Work that's still running, with `loading`, replaced by the result when it's done.

</UseFor>
<UseInstead>

- **A status that has to stay until it's dealt with:** <DocLink to="Components/Feedback/Section Message" />.
- **An announcement for the whole page:** <DocLink to="Components/Feedback/Banner" />.
- **A short status beside what it's about:** <DocLink to="Components/Feedback/Inline Message" />.
- **A decision the user has to make before going on:** <DocLink to="Components/Overlays/Modal Dialog" />.

</UseInstead>

<Section title="Variants">

`tone` sets the tile: `default` is a taupe tile with a dot, `success` green, `information` blue,
`warning` orange, and `error` red, each with its status icon. `loading` shows a Spinner in place of
the tile, and its title takes the muted loading text color. The card itself looks the same in every
tone. `info`, the earlier name for `information`, and `appearance`, the earlier name for `tone`, are
still accepted.

<Example of={ToastStories.Tones} />

</Section>

<Section title="Behavior">

<Subsection title="Expanded and collapsed">

`expanded` decides whether the description and actions are shown; collapsed, the toast is its title
alone. It's on by default. Toast Group turns it off while toasts are stacked and on while the stack is
hovered or focused, so a description or action is only seen once someone reaches for the stack.

<Example of={ToastStories.ExpandedCollapsed} />

</Subsection>

<Subsection title="Dismissing">

The dismiss button shows unless `isDismissible` is `false`, and calls `onDismiss`. Toast doesn't hide
itself: Toast Group removes it. Turn dismissing off for a `loading` toast, which is replaced when the
work finishes rather than closed.

<Example of={ToastStories.Content} caption="Title only, a description with no actions, and a loading toast with no dismiss button." />

</Subsection>

</Section>

<Section title="Do and don't">

<Guidelines>
<Do caption="Say what happened in the title, and put anything more in the description." code={`toast.success('Matter archived', { description: 'You can find it under Archived matters.' });`}>
  <Toast tone="success" title="Matter archived" description="You can find it under Archived matters." />
</Do>
<Dont caption="Put everything in the title. It's the only part shown while the toast is stacked." code={`toast.success('The matter was archived and can now be found under Archived matters');`}>
  <Toast tone="success" title="The matter was archived and can now be found under Archived matters" />
</Dont>
<Do
  caption="Use toast actions as shortcuts to something people can also do elsewhere, such as undo."
  code={`toast.success('Matter archived', {
    actions: <Button size="xs" prominence="tertiary">Undo</Button>,
});`}
>
  <Toast tone="success" title="Matter archived" actions={<Button size="xs" prominence="tertiary">Undo</Button>} />
</Do>
<Dont
  caption="Put the only way to do something important in a toast. It disappears on its own, and its actions only show while the stack is expanded."
  code={`toast.warning('New billing terms', {
    actions: <Button size="xs" prominence="tertiary">Accept terms</Button>,
});`}
>
  <Toast tone="warning" title="New billing terms" actions={<Button size="xs" prominence="tertiary">Accept terms</Button>} />
</Dont>
<Do caption="Write a loading title that says what's happening. Loading reads no status of its own." code={`toast.loading('Uploading contract.pdf…');`}>
  <Toast tone="loading" title="Uploading contract.pdf…" isDismissible={false} />
</Do>
<Dont caption="Leave a loading title vague. Screen readers hear only these words." code={`toast.loading('Please wait');`}>
  <Toast tone="loading" title="Please wait" isDismissible={false} />
</Dont>
</Guidelines>

</Section>

<Section title="Accessibility">

- Toast renders a `div` with `role="status"`, a polite live region. Pass another `role` only when the
  toast plays a different part on the page.
- The tile and the Spinner are hidden from assistive technology. For `success`, `information`,
  `warning`, and `error`, visually hidden text with the tone's name, such as "Error:", is read before
  the title, so the meaning doesn't depend on color. `default` and `loading` read none, so the title
  has to say it. Translate it with `statusLabel`.
- The dismiss button is an Icon Button named by `dismissLabel`, "Dismiss" by default, which also
  shows as its tooltip on hover and focus, as on Section Message. In a Toast Group the tooltip is
  drawn behind the stack for now, until overlays share one stacking order.
- The card isn't focusable. Tab reaches the dismiss button first, since it sits beside the title,
  then the actions.
- A collapsed toast doesn't render its description or actions at all, so they're neither read nor
  reachable until it's expanded.

<Keyboard>
  <Key keys="Tab">Moves to the dismiss button, then to each action.</Key>
  <Key keys="Enter">On the dismiss button, calls `onDismiss`.</Key>
  <Key keys="Space">On the dismiss button, calls `onDismiss`.</Key>
</Keyboard>

</Section>
